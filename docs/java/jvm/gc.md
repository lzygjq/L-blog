# 垃圾回收

## 一、对象什么时候可以回收

**当一个对象不再被任何有效引用指向时，它就是垃圾。** 判断「不再被引用」有两种思路，JVM 选了后者的原因必须讲清：

| 算法 | 原理 | 缺陷 |
|---|---|---|
| 引用计数法 | 被引用一次计数 +1，归零可回收 | **循环引用无法回收**（A↔B 互指，计数都不为 0 但已不可达） |
| 可达性分析（JVM 采用） | 从 GC Roots 出发沿引用链搜索，搜不到的对象可回收 | 需要遍历，但正确性完备 |

### GC Roots 包括哪些

1. **虚拟机栈中局部变量表引用的对象**（正在执行的方法里的变量）
2. **方法区中类静态属性引用的对象**（static 字段）
3. **方法区中常量引用的对象**（final 常量、字符串常量池）
4. **本地方法栈中 JNI 引用的对象**（native 方法里的引用）

记忆法：**「活跃的引用起点」**——正在跑的线程栈、类的静态持有、常量池、本地代码持有，都是程序当前「够得着」的入口。

## 二、四种引用：回收时机的分级控制

| 引用类型 | 回收时机 | 典型场景 |
|---|---|---|
| 强引用（`new`） | GC Roots 可达就永不回收，宁肯 OOM | 普通对象引用 |
| 软引用 `SoftReference` | 内存不足时回收（GC 后仍不够才动手） | 缓存（图片/数据缓存） |
| 弱引用 `WeakReference` | 只要发生 GC 就回收，不看内存 | `ThreadLocal` 的 Entry Key、`WeakHashMap` |
| 虚引用 `PhantomReference` | 随时可回收，回收时入引用队列，由 Reference Handler 线程通知 | 管理**直接内存**释放（`Cleaner` 机制） |

三个理解要点：

1. **软引用的设计意图是「缓存」**：内存充裕时留着加速，紧张时自动让位，比手写 LRU 更省心——但注意它只保证「内存不足才清」，不能替代容量控制。
2. **弱引用解决的是「生命周期绑定」**：`ThreadLocal` 的 key 用弱引用，就是为了让 ThreadLocal 对象本身被回收后，Entry 的 key 自动失效（虽然 value 仍需 remove 防泄漏——这是 ThreadLocal 内存泄漏的经典考点，见[并发板块](/java/concurrent/)）。
3. **虚引用是唯一能感知「对象被回收」的机制**：`NIO` 的 `DirectByteBuffer` 靠它做堆外内存的清理回调——这也是「虚引用管理直接内存」这句话的由来。

## 三、三种回收算法

| 算法 | 过程 | 优点 | 缺点 | 实际应用 |
|---|---|---|---|---|
| 标记-清除 | 标记可回收对象 → 逐块清除 | 实现简单、速度快 | **内存碎片**，大对象分配可能失败 | CMS 的并发清理阶段 |
| 标记-整理 | 标记存活对象 → 压缩到一端 → 清理边界外 | 无碎片 | 需移动对象，**效率低** | 老年代（Serial Old 等） |
| 复制 | 内存分两块，存活对象复制到空块后整块清空 | 无碎片、分配快（指针碰撞） | **内存利用率仅 50%** | 新生代（Eden/Survivor，用 8:1:1 缓解浪费） |

**为什么新生代用复制、老年代用标记-整理/清除**——这是算法与「对象存活率」的匹配：

```
新生代：对象朝生夕死，每次 GC 存活率极低 → 复制成本 ∝ 存活对象数，所以便宜
老年代：对象存活率高 → 复制成本 ∝ 几乎所有对象，极贵 → 只能用标记类算法
```

## 四、分代回收：完整流程

```
堆
├── 新生代（1/3）：Eden(8) + Survivor-from(1) + Survivor-to(1)
└── 老年代（2/3）
```

**一次典型的 Minor GC 流程**：

1. 新对象分配在 **Eden**；
2. Eden 满 → 标记 Eden + 当前 Survivor（from）中的存活对象；
3. 用**复制算法**把它们复制到另一个 Survivor（to），年龄 +1，然后清空 Eden 与 from；
4. 下一轮 GC 时 from / to 角色互换（总有一块 Survivor 是空的，作为复制目标）；
5. 年龄达到阈值（`-XX:MaxTenuringThreshold`，默认 15）的对象**晋升老年代**；
6. **动态年龄判定**：Survivor 中同年龄对象总和超过一半时，大于等于该年龄的直接晋升（不等到 15）——这是"为什么对象没到 15 岁就进了老年代"的答案；
7. **大对象**（超过 `-XX:PretenureSizeThreshold`）直接进老年代，避免来回复制。

### GC 分类

| 类型 | 范围 | 触发时机 |
|---|---|---|
| Minor GC / Young GC | 新生代 | Eden 满 |
| Major GC / Old GC | 老年代 | 老年代空间不足（CMS 特有语义） |
| Mixed GC | 新生代 + 部分老年代 | G1 专有，见[收集器](/java/jvm/collectors) |
| **Full GC** | 整个堆 + 方法区 | 老年代不足、元空间不足、显式 `System.gc()`、晋升失败/担保失败 |

**调优的核心关注点就是「减少 Full GC」**——它 STW 最长，且往往意味着堆参数或对象分配行为存在问题。

## 五、面试口径

> 「对象没有任何有效引用指向它时就可回收。判断方式有两种：引用计数法有循环引用问题，所以 JVM 用可达性分析，从 GC Roots 出发沿引用链搜索，搜不到的可回收——GC Roots 包括栈中局部变量引用的对象、方法区静态属性和常量引用的对象、本地方法栈 JNI 引用的对象。四种引用控制回收时机：强引用宁肯 OOM 也不收，软引用内存不足时收适合做缓存，弱引用一 GC 就收、ThreadLocal 用它，虚引用配合引用队列用于释放直接内存。三种算法：标记-清除有碎片、标记-整理要移动对象效率低、复制没有碎片但费一半内存。分代回收就是把存活率低的年轻代交给复制算法，老年代用标记类算法，对象在 Survivor 间复制到年龄阈值后晋升老年代。」
