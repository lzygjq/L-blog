# 运行时数据区

## 一、全景：五个区域 + 一个「编外」

```
JVM 运行时数据区
├── 线程私有（随线程创建和销毁）
│   ├── 程序计数器      字节码行号指示器
│   ├── 虚拟机栈        方法调用的栈帧链
│   └── 本地方法栈      native 方法调用
└── 线程共享（随 JVM 启动和关闭）
    ├── 堆             对象实例与数组（GC 主战场）
    └── 方法区         类信息、常量、静态变量（JDK8 起由元空间实现，位于本地内存）
直接内存（不属于运行时数据区，不受 JVM 内存回收管理）
```

**记忆锚点**：私有三个不涉及并发、共享两个是 GC 与调优的主要对象。面试让你画图时，这个分类框架比背细节重要。

## 二、程序计数器：唯一不会 OOM 的区域

- **作用**：记录当前线程正在执行的字节码指令地址（行号）。分支、循环、跳转、异常处理都靠它恢复到正确位置。
- **特点**：线程私有、每个线程一份；**内存占用极小，是唯一不会抛 OutOfMemoryError 的区域**。
- **为什么需要**：CPU 在多线程间轮转执行，线程被切换出去再切回来必须知道「刚才执行到哪了」——计数器就是这个书签。

## 三、虚拟机栈：方法执行的内存模型

每个线程对应一个虚拟机栈，栈内是一串栈帧；每次方法调用压入一个栈帧，返回时弹出。栈帧包含：

| 组成 | 内容 |
|---|---|
| 局部变量表 | 方法参数 + 局部变量（基本类型存值，引用类型存引用） |
| 操作数栈 | 字节码运算的工作区 |
| 动态链接 | 指向运行时常量池中该方法的引用 |
| 方法返回地址 | 方法退出后回到调用处的位置 |

**每个线程同一时刻只有一个活动栈帧**——即栈顶那个正在执行的方法。

两个高频问题：

**垃圾回收涉及栈内存吗？** 不涉及。栈帧随方法结束自动弹栈释放，不需要 GC 参与；GC 管的是堆里的对象。

**栈越大越好吗？** 不是。栈大小（`-Xss`，默认约 1M）决定单线程内存占用，二者是此消彼长：

```
机器 512M 可用内存
- Xss=1M  → 理论上限约 512 个线程
- Xss=2M  → 理论上限约 256 个线程
```

所以 `-Xss` 的取值是「单方法调用深度」和「并发线程数」之间的权衡：递归深/框架调用链长可以适当放大，高并发服务则要克制。

**栈内存溢出（StackOverflowError）的两种成因**：

1. 栈帧过多——最常见是递归没有正确的终止条件；
2. 栈帧过大——单个方法局部变量表异常臃肿。

## 四、局部变量是否线程安全

判据只有一条：**变量是否「逃离」了方法作用范围**。

| 情形 | 结论 |
|---|---|
| 方法内创建、方法内使用、不外泄 | 线程安全（各线程有各自的栈帧） |
| 作为返回值返回、交给其他线程、存入共享集合 | 需要按共享对象处理 |

注意「没逃离」的前提往往被隐式打破：局部变量引用的对象本身若是共享对象（如静态 Map），或方法内启动了新线程持有它，逃逸就发生了。这也是编译器逃逸分析能做的优化（栈上分配）的基础。

## 五、堆：GC 的主战场

堆是 JVM 中最大的一块线程共享内存，存放对象实例和数组，内存不足时抛 `OutOfMemoryError: Java heap space`。

```
堆
├── 新生代（约 1/3）
│   ├── Eden（8）
│   └── Survivor × 2：from / to（各 1）
└── 老年代（约 2/3）
```

- 新对象优先分配在 Eden；Eden 满触发 Minor GC，存活对象经复制算法进 Survivor；
- 对象在 Survivor 间来回复制，每复制一次年龄 +1，达到阈值（默认 15）晋升老年代；
- 大对象可直接进老年代（避免 Eden/Survivor 间大量复制）；
- 比例由 `-XX:NewRatio`（默认 2，即老年代:新生代 = 2:1）与 `-XX:SurvivorRatio`（默认 8，即 Eden:S0:S1 = 8:1:1）控制。

**JDK 1.7 → 1.8 的关键变化**：1.7 有**永久代**（PermGen，堆内，存类信息、静态变量、常量）；1.8 移除永久代，改由**元空间**（Metaspace）承载，使用**本地内存**——好处是不再与堆争空间、不受 `-Xmx` 约束，代价是要单独设 `-XX:MaxMetaspaceSize` 防止无限增长。

补充一个工程细节：**TLAB**（Thread Local Allocation Buffer）——Eden 按线程预先划小片，对象分配先在各自 TLAB 内进行（无锁分配），用尽再申请新 TLAB，这是 JVM 在高并发下分配对象的效率保障。

## 六、方法区：类元数据的家

- **共享性**：线程共享，虚拟机启动时创建、关闭时释放。
- **存什么**：类的结构信息（字段、方法、父类、接口）、运行时常量池、静态变量、即时编译后的代码缓存。
- **异常**：内存不足时 `OutOfMemoryError: Metaspace`。
- **运行时常量池**：class 文件常量池（类名、方法名、参数类型、字面量）在类加载后进入运行时常量池；**符号引用在解析阶段替换为直接引用**（比如方法名 → 内存地址）。

JDK8 之后「方法区」是规范层面的概念，落地实现是元空间（本地内存）——面试时把「规范」和「实现」区分开说，是很自然的加分点。

## 七、直接内存：NIO 的性能开关

不属于 JVM 运行时数据区、由操作系统管理、不受 GC 管辖，典型用途是 **NIO 的数据缓冲区**。

```
常规 IO：  磁盘 → 内核缓冲区 → JVM 堆内存（byte[]）→ 复制给内核 → 网络
NIO：      磁盘 → 内核缓冲区 → 直接内存（堆外）→ 直接发往网络
```

少一次堆内堆外拷贝，所以读写性能更高；代价是分配/回收成本高（不受 GC 管理，靠 Cleaner/虚引用机制释放），且要显式限制上限（`-XX:MaxDirectMemorySize`），否则可能撑爆物理内存。

## 八、堆与栈的对比（面试标准答案）

| 维度 | 栈（虚拟机栈） | 堆 |
|---|---|---|
| 存储内容 | 局部变量、方法调用信息 | 对象实例、数组 |
| 线程归属 | 私有 | 共享 |
| 回收方式 | 弹栈自动释放，无 GC | GC 回收 |
| 溢出异常 | StackOverflowError | OutOfMemoryError |
| 分配效率 | 高（指针移动） | 相对低（需分配与 GC 管理） |

## 九、面试口径

> 「JVM 运行时数据区分线程私有和共享两类。私有的三个：程序计数器记录字节码行号、是唯一不会 OOM 的区域；虚拟机栈描述方法执行，栈帧随调用入栈出栈，弹栈自动释放因此不涉及 GC；本地方法栈服务 native 方法。共享的两个：堆存对象实例，是 GC 的主战场，分为新生代老年代；方法区存类信息和常量，JDK8 之后由元空间实现、用的是本地内存。此外还有不受 JVM 管理的直接内存，用于 NIO 减少一次拷贝。」
