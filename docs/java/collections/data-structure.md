# 数据结构与算法复杂度

集合框架的性能差异，根子上都由**底层数据结构的特性**决定。所以讨论 `ArrayList` 快还是 `LinkedList` 快之前，得先把数组、链表这些底座，以及衡量它们的语言——**大 O 表示法**——说清楚。

## 一、为什么要做复杂度分析

同一段逻辑，用不同写法实现，性能可能差一个数量级。复杂度分析解决两个问题：

1. **写代码时**：知道自己选的写法在数据量变大后会怎样劣化；
2. **读代码时**：能判断别人写的代码好坏，而不是只能凭感觉。

它衡量的是**代码执行时间随数据规模增长的变化趋势**，不纠结于「这段代码实际跑了几毫秒」——后者受机器、编译器、JIT 影响太大，无法横向比较。

## 二、大 O 表示法

以「求 1~n 累加和」为例：

```java
public int sum(int n) {
    int sum = 0;                      // 1 次
    for (int i = 1; i <= n; i++) {    // n 次判断 + n 次自增
        sum = sum + i;                // n 次
    }
    return sum;                       // 1 次
}
```

假设每行代码执行耗时固定为 1ms，总执行次数是 `3n + 3`，于是 `T(n) = (3n + 3) * 1ms`。

**大 O 表示法的本质**：不表示代码真正的执行时间，而是表示**执行时间随数据规模增长的变化趋势**。当 n 足够大时，**低阶项、常量、系数**三部分都不左右增长趋势，可以忽略，只保留最大的量级：

```text
T(n) = O(3n + 3)  →  T(n) = O(n)
```

所以 `O(3n + 3)`、`O(300n + 1000)`、`O(n)` 描述的是**同一条增长曲线**。

## 三、常见复杂度

| 描述 | 表示形式 | 典型代码形态 |
|---|---|---|
| 常数 | `O(1)` | 无循环，或循环次数与 n 无关 |
| 对数 | `O(log n)` | `i = i * 2` 这类循环变量倍增 |
| 线性 | `O(n)` | 单层循环 |
| 线性对数 | `O(n * log n)` | 循环体内嵌套一个对数级操作 |
| 平方 | `O(n²)` | 双重循环 |
| 立方 | `O(n³)` | 三重循环 |
| k 次方 | `O(n^k)` | k 层循环嵌套 |
| 指数 | `O(2^n)` | 递归中每次分裂两支 |
| 阶乘 | `O(n!)` | 全排列 |

**速记口诀：常对幂指阶**（常数 → 对数 → 幂 → 指数 → 阶乘），性能从高到低。

### 各形态的代码判读

**`O(1)`——执行次数与 n 无关**

```java
public int test01(int n) {
    int i = 0;
    int j = 1;
    return i + j;
}

public void test02(int n) {
    int sum = 0;
    for (int i = 0; i < 100; i++) {   // 固定 100 次，与 n 无关
        sum = sum + i;
    }
    System.out.println(sum);
}
```

两个方法都是 `O(1)`。关键判据：**只要代码的执行时间不随 n 增大而增大，复杂度就是 `O(1)`**——哪怕里面有个跑了 100 次的循环。

**`O(n)` 与 `O(n²)`**

```java
public int sum(int n) {                  // O(n)
    int sum = 0;
    for (int i = 1; i <= n; i++) {
        sum = sum + i;
    }
    return sum;
}

public int sum2(int n) {                 // O(n²)
    int sum = 0;
    for (int i = 1; i <= n; i++) {
        for (int j = 1; j <= n; j++) {
            sum = sum + i * j;
        }
    }
    return sum;
}
```

**`O(log n)`——循环变量成倍增长**

```java
public void test04(int n) {
    int i = 1;
    while (i <= n) {
        i = i * 2;
    }
}
```

复杂度分析就是要弄清**代码执行次数与数据规模 n 的关系**：

| 代码执行次数 x | 变量 i 的值 |
|---|---|
| 1 | 2 |
| 2 | 4 |
| 3 | 8 |
| 4 | 16 |
| x | 2^x |

由 `2^x = n` 得 `x = log₂n`，即 `O(log n)`。

同样的形式，把 `i = i * 2` 换成 `i = i * 10`，答案是 `O(log n)`——**底数是几不影响增长趋势的量级**，所以统一写成 `O(log n)`。

**`O(n * log n)`——线性外套对数**

```java
public void test05(int n) {
    for (int i = 0; i <= n; i++) {
        test04(n);        // 内部是 O(log n)
    }
}
```

外层 `O(n)` × 内层 `O(log n)` = `O(n * log n)`。归并排序、快排的平均复杂度都属于这一档。

## 四、空间复杂度

空间复杂度全称**渐进空间复杂度**，表示算法占用的**额外存储空间**与数据规模之间的增长关系。

```java
public void test(int n) {          // O(1)：只用了 i、sum 两个常量级变量
    int i = 0;
    int sum = 0;
    for (; i < n; i++) {
        sum = sum + i;
    }
    System.out.println(sum);
}

void print(int n) {                // O(n)：申请了长度为 n 的数组
    int[] a = new int[n];
    for (int i = 0; i < n; ++i) {
        a[i] = i * i;
    }
    for (int i = n - 1; i >= 0; --i) {
        System.out.println(a[i]);
    }
}
```

常见空间复杂度只有 `O(1)`、`O(n)`、`O(n²)` 三档，对数阶几乎用不到——所以**空间复杂度比时间复杂度好分析得多**。

## 五、数组

> 数组（Array）是一种用**连续的内存空间**存储**相同数据类型**数据的线性数据结构。

```java
int[] array = {22, 33, 88, 66, 55, 25};
```

因为内存连续，数组支持**按索引随机访问**——这是它最大的优势。

### 数组的寻址

计算机怎么根据下标找到元素？靠**寻址公式**：

```text
a[i] = baseAddress + i * dataTypeSize

baseAddress  ：数组首地址
dataTypeSize ：元素类型大小，int 为 4 字节
```

### 数组为什么下标从 0 开始

> 思考：为什么数组索引从 0 开始呢？假如从 1 开始不行吗？

对比两个寻址公式：

| 索引起始 | 寻址公式 | 代价 |
|---|---|---|
| 从 0 开始 | `a[i] = baseAddress + i * dataTypeSize` | 直接乘加，无额外指令 |
| 从 1 开始 | `a[i] = baseAddress + (i - 1) * dataTypeSize` | 每次多一条减法指令 |

对 CPU 而言，从 1 开始就意味着**每次寻址都多一条减法指令**。这不是「能不能」的问题，而是性能上的取舍——所以 0 胜出。

### 数组的查找

| 场景 | 做法 | 复杂度 |
|---|---|---|
| 已知下标 | 寻址公式直接定位 | `O(1)` |
| 未知下标 | 从前往后遍历 | `O(n)` |
| 未知下标但**已排序** | 二分查找 | `O(log n)` |

### 数组的插入与删除

数组是一段连续的内存空间，**为了保证连续性**，插入和删除后往往需要成片挪动元素：

- 最好情况：插在末尾 / 删在末尾，`O(1)`；
- 最坏情况：插在头部 / 删在头部，要挪动全部 n 个元素，`O(n)`；
- 平均情况：`O(n)`。

这也解释了为什么「频繁在头部增删」的场景应该换链表。

## 六、链表

> 链表在物理存储单元上是**非连续、非顺序**的存储结构，靠指针把散落的结点串起来。

### 单向链表

每个结点包含两部分：**数据域**（存数据元素）和**指针域**（存下一个结点的地址，叫**后继指针 `next`**）。

```java
private static class Node<E> {
    E item;
    Node<E> next;

    Node(E element, Node<E> next) {
        this.item = element;
        this.next = next;
    }
}
```

若有结点 `B`，它的下一个结点是 `C`，则表示为 `B.next == C`。

**时间复杂度**：只有查询**头结点**不需要遍历，`O(1)`；查询其他结点要顺着 `next` 走，`O(n)`。增删同理——**只有操作头结点是 `O(1)`**，其他结点得先遍历找到位置，`O(n)`。

### 双向链表

双向链表的结点多一个**前驱指针 `prev`**，指向前一个结点，因此支持**双向遍历**。

```java
private static class Node<E> {
    E item;
    Node<E> next;
    Node<E> prev;

    Node(Node<E> prev, E element, Node<E> next) {
        this.item = element;
        this.next = next;
        this.prev = prev;
    }
}
```

**时间复杂度**：查询头尾结点 `O(1)`、平均查询 `O(n)`；头尾增删 `O(1)`、其他结点增删 `O(n)`。最关键的一点——**给定某个结点时，增删是 `O(1)`**（因为不用再遍历找前驱）。

### 单双向链表对比

| 维度 | 单向链表 | 双向链表 |
|---|---|---|
| 指针 | 只有 `next` | `next` + `prev` |
| 空间 | 省（少一个指针） | 费（多一个指针） |
| 遍历 | 只能单向 | 支持双向 |
| 查询 | 头 `O(1)`，其他 `O(n)` | 头尾 `O(1)`，其他 `O(n)` |
| 增删 | 头 `O(1)`，其他 `O(n)` | 头尾 `O(1)`，给定结点 `O(1)`，其他 `O(n)` |

一句话总结：**双向链表用「两个指针的空间」换「双向遍历 + 给定结点 O(1) 增删」的灵活性**——这正是 `LinkedList` 选择双向链表的原因。

## 七、高频考点

| 问题 | 答案要点 |
|---|---|
| 什么是时间复杂度？ | 表示算法的**执行时间**与**数据规模**之间的增长关系 |
| 常见时间复杂度有哪些？ | `O(1)`、`O(log n)`、`O(n)`、`O(n * log n)`、`O(n²)`，速记「常对幂指阶」 |
| 什么是空间复杂度？ | 表示算法占用的**额外存储空间**与数据规模之间的增长关系，常见只有 `O(1)`、`O(n)`、`O(n²)` |
| 数组下标为什么从 0 开始？ | 寻址公式 `base + i * size` 无需额外减法指令，CPU 少一条指令 |
| 数组插入删除的复杂度？ | 需要挪动元素保证连续性，最好 `O(1)`、最坏 `O(n)`、平均 `O(n)` |
| 单双向链表的区别？ | 双向多一个 `prev` 指针，多耗空间换双向遍历与给定结点 `O(1)` 增删 |
