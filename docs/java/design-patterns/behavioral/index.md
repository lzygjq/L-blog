# 行为型模式 · 导览

行为型模式关注**对象之间的职责分配与通信方式**——把"变化的算法、变化的状态、变化的请求"从稳定的调用流程中剥离出来。它是三类模式中数量最多（11 个）的一类，但主线只有一条：**找到那个"会变的东西"，给它一个独立的抽象。**

| 意图 | 模式 | 一句话 | 状态 |
|---|---|---|---|
| **算法与流程** | 模板方法 Template Method | 父类定骨架，子类填步骤 | 待整理 |

| | 命令 Command | 把"请求"封装成对象，支持排队、撤销、日志 | 待整理 |

## 二、四组关键辨析（面试高频）

### 2.1 策略 vs 状态——结构相同，意图相反

两者都是"把行为委托给一个抽象对象"，**代码形状几乎一模一样**，区别在于**谁决定切换**：

| 维度 | 策略 | 状态 |
|---|---|---|
| 切换的发起者 | **客户端**（调用方显式选择并注入） | **状态对象自己**（内部触发转移） |
| 调用方是否知道具体实现 | 知道，且主动选择 | 通常不知道，状态流转是封闭的 |
| 状态之间的耦合 | 策略彼此独立、互不感知 | 状态之间存在明确的转移关系 |
| 典型场景 | 支付渠道、排序算法、计费规则 | 订单状态机、审批流、连接生命周期 |

一句话记忆：**策略是"我挑一个用"，状态是"走着走着就变了"**。

### 2.2 策略 vs 模板方法——组合 vs 继承

| 维度 | 模板方法 | 策略 |
|---|---|---|
| 复用手段 | **继承**（子类覆写钩子方法） | **组合**（注入算法对象） |
| 绑定时机 | 编译期，静态 | 运行期，可动态替换 |
| 变化粒度 | 整个算法的**部分步骤** | 整个算法 |
| 代价 | 子类与父类强耦合，受继承体系限制 | 类数量增加，调用方需要知道策略的存在 |

Spring 中两者都在用：`JdbcTemplate` 是模板方法（`execute` 固定流程，`RowMapper` 变化），`PlatformTransactionManager` 是策略（业务无感，容器注入）。

### 2.3 责任链 vs 装饰者——传递方式不同

- **装饰者**：请求**必然**穿过每一层，层层加强（`BufferedInputStream`）。
- **责任链**：请求**可能中途终止**，由某个节点处理完即结束（Servlet Filter 中链断了就不往下走）。

### 2.4 观察者 vs 中介者——通信拓扑不同

- **观察者**：目标与订阅者之间是**一对多**的星形，但订阅者之间**互不认识**。
- **中介者**：把对象之间**多对多的网状依赖**收敛到一个中心节点，各方都只与中介者通信。

## 三、面试高频速答

- **Servlet Filter / Spring Interceptor / Netty Pipeline 是同一种思想吗？** 都是责任链，但传递载体和终止方式不同（Filter 用 `FilterChain`，Interceptor 用 `HandlerExecutionChain`，Netty 用双向 `ChannelPipeline`）。
- **Spring 的 `ApplicationEventPublisher` 是观察者模式吗？** 思想一致（发布-订阅 + 多播），但实现是应用内事件总线：监听器注册到容器，`publishEvent` 遍历通知，可配 `@Async` 异步化。
- **JDK 里哪些是迭代器？** 所有 `Collection` 的 `iterator()`，以及 `Scanner`、`ResultSet`（数据库游标）等。
- **哪里用了命令模式？** `Runnable` / `Callable`（把任务封装成对象交给线程池）、请求的日志与重放、数据库事务的 undo 日志。
- **责任链在业务里的典型形态？** 参数校验链、风控规则链、审批流、优惠券叠加计算。
- **状态机必须用状态模式吗？** 不一定。状态少且转移简单时 `enum + switch` 更直观；状态多、转移复杂、每个状态下行为差异大时才值得引入状态模式或专业状态机引擎（如 Spring StateMachine）。

## 四、学习顺序建议

```
模板方法 → 策略 → 责任链 → 命令      （算法与流程，最常用、最好落地）
   ↓
状态 → 观察者 → 中介者               （状态与协作，结合业务状态机理解）
   ↓
迭代器 → 备忘录 → 访问者 → 解释器    （偏向框架与编译器领域，理解边界即可）
```

**优先级提醒**：从面试与工程收益看，**策略、责任链、模板方法、观察者**这四个是性价比最高的（Spring 源码里随处可见）；**访问者与解释器**使用频率低，重点掌握"为什么需要它"和"代价是什么"，不必强记实现细节。
