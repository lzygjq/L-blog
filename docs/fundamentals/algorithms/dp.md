# 动态规划与算法思想

> 上一篇：[排序](/fundamentals/algorithms/sorting)　|　下一篇：[海量数据处理](/fundamentals/algorithms/high-volume)

前面五篇都在讨论"数据结构"——数据怎么组织。从这一篇起转向"算法思想"——**问题怎么建模**。而动态规划（DP）是其中最难自学的部分，因为**它没有固定套路，只有一个可训练的思考流程**。

**先把结论放前面**：

1. **DP 的难点在"定义状态"，不在写代码**。状态定义对了，转移方程几乎是自然写出来的；状态定义错了，怎么调都是错的。所以五步法的第一步永远是"状态是什么、代表什么含义"。
2. **DP = 分治 + 消除重叠子问题**。它能用的两个前提是**最优子结构**和**无后效性**——**少了任何一个，都只能退化成搜索**。
3. **贪心是 DP 的特例**：当"局部最优能推出全局最优"时，可以省掉"枚举所有选择"这一步。**判断能不能贪心，靠的是找反例，不是靠感觉。**
4. **经典模型只有五个**：背包、LIS、两个字符串的编辑距离/LCS、区间 DP、状态压缩。**绝大多数 DP 题都是这几个模型的变体**——所以这一篇的重点是记"模型"而不是记"题"。

## 一、DP 的五步法 {#five-steps}

DP 是可以按流程硬推的，顺序不能乱：

| 步骤 | 要回答的问题 | 出错后果 |
|---|---|---|
| **① 定义状态** | `dp[i]` / `dp[i][j]` 的**确切含义**是什么？ | 定义模糊 → 后面全错 |
| **② 找转移方程** | `dp[i]` 由哪些**更小的状态**推出？ | 漏掉某个选择 → 答案偏大/偏小 |
| **③ 初始化** | `dp[0]` / 边界值是什么？ | 边界错 → 小数据对、大数据错 |
| **④ 确定遍历顺序** | 谁先算、谁后算？ | 顺序错 → 用到还没算出来的值 |
| **⑤ 推导返回值** | 答案是 `dp[n]` 还是 `max(dp[...])`？ | 差一步 |

### 一个最小例子：爬楼梯 {#climbing-stairs}

**问题**：每次可以爬 1 级或 2 级，爬到 n 级有多少种方法。

| 步骤 | 内容 |
|---|---|
| ① 状态 | `dp[i]` = 爬到第 i 级台阶的**方法数** |
| ② 转移 | 到第 i 级，只能从 `i-1`（爬 1 级）或 `i-2`（爬 2 级）来 → **`dp[i] = dp[i-1] + dp[i-2]`** |
| ③ 初始 | `dp[0] = 1`（不走就算一种）、`dp[1] = 1` |
| ④ 顺序 | `i` 从 2 到 n，**正序**（`dp[i]` 依赖更小的下标） |
| ⑤ 返回 | `dp[n]` |

```java
public int climbStairs(int n) {
    if (n <= 1) return 1;
    int prev2 = 1, prev1 = 1;               // 只要前两个值，空间 O(1)
    for (int i = 2; i <= n; i++) {
        int cur = prev1 + prev2;
        prev2 = prev1;
        prev1 = cur;
    }
    return prev1;
}
```

**注意第 ④ 步的价值**：`dp[i]` 只依赖前两个值，所以**不需要整个数组**、只要两个变量——**这就是"状态压缩"的最简单形态**（更复杂的形式见 [空间优化](#space-opt)）。

### 自顶向下（记忆化）vs 自底向上（递推） {#top-down-vs-bottom-up}

同一个问题的两种写法，**建议先写记忆化版**：

| | 自顶向下（记忆化搜索） | 自底向上（递推） |
|---|---|---|
| 形态 | 递归 + 缓存表 | 循环填表 |
| 优点 | **思路直接**（照抄暴力递归加个 `memo`）；**只算用得到的状态** | **无递归栈开销**；容易做空间优化；常数更小 |
| 缺点 | 递归栈深度限制；常数开销 | **必须自己排好遍历顺序**（错序就是静默错误） |
| 适合 | **先想清楚状态定义** | 状态维度大、要优化空间时 |

**实战建议**：**先用记忆化写出正确解，再改写成递推版做优化。** 直接从递推入手，很容易在"遍历顺序"上翻车（尤其是二维以上）。

## 二、贪心、分治、DP：三个思想的分界 {#paradigms}

这三个经常被混在一起考。它们的分界非常清晰：

| | **分治** | **贪心** | **动态规划** |
|---|---|---|---|
| 子问题 | **相互独立** | 只保留一个局部最优 | **相互重叠** |
| 决策 | 无关，各管各的 | 每步取当下最好，**不回头** | **枚举所有选择**，取最优 |
| 是否能回溯 | — | ❌ **不能** | ✅ 通过状态比较"回溯" |
| 复杂度 | `O(n log n)` 常见 | 通常 `O(n log n)` 或 `O(n)` | 通常 `O(n²)` 或更高 |
| 反例 | — | **找零钱、0-1 背包**（贪心会错） | — |
| 代表 | 归并排序、二分查找 | Dijkstra、Huffman、活动选择 | 背包、LIS、编辑距离 |

**判断用哪个，问三个问题**：

1. **子问题是否重叠？** 是 → DP 或贪心；否 → 分治。
2. **能否证明"局部最优 = 全局最优"？** 能 → 贪心；不能 → DP。
3. **有没有后效性？** 有 → **两个都不行**，只能搜索（回溯）。

### 贪心的两个经典反例 {#greedy-counterexamples}

**反例一：找零钱**。面额 `[1, 3, 4]`，凑 6 元，最少几张？

```text
贪心（每次取最大面额）：4 + 1 + 1 = 3 张
最优解：                 3 + 3     = 2 张
```

**贪心错在：取 4 之后，剩下的 2 无法用 3 凑整**——**当前最优损害了后续选择**。这正是"贪心选择性质"不成立的典型表现。

**反例二：0-1 背包**。按"单位价值最高"贪心取，可能因为某件物品塞满剩余空间、导致更好的组合进不来。

> **判断贪心是否可行的通用方法：找反例。** 找到反例 = 不能用贪心；**找不到反例不等于正确**（这是数学证明的事）。**面试里被问"能不能贪心"，标准答法是给出反例或说明为什么交换论证成立。**

### 什么情况下贪心是对的 {#when-greedy-works}

贪心需要**同时**满足三条：

| 条件 | 含义 |
|---|---|
| **最优子结构** | 全局最优包含子问题的最优（与 DP 共享） |
| **贪心选择性质** | **每一步的局部最优一定能构成某个全局最优解** |
| **无后效性** | 当前决策不影响"未来可用状态的性质" |

**Dijkstra 能贪心，就是因为它满足了第三条**——非负权保证了"已确定的距离不会再变小"（这就是为什么有负权就崩溃，见 [Dijkstra](/fundamentals/algorithms/graph#dijkstra)）。**"贪心的正确性依赖某个前提"这件事，比贪心本身更值得记住。**

## 三、五个经典模型 {#classic-models}

**记住模型而不是题目**——DP 题的复用率极高。

### 模型一：背包 {#knapsack}

背包有三个变种，**它们的唯一区别是"物品能不能重复拿"**，而这一点直接决定了**遍历方向**。

| 变种 | 每件物品 | 遍历顺序 | 复杂度 |
|---|---|---|---|
| **0-1 背包** | 最多拿 1 次 | 容量 **逆序** | `O(n·W)` |
| **完全背包** | 可以拿无限次 | 容量 **正序** | `O(n·W)` |
| **多重背包** | 有件数上限 | 二进制拆分后转为 0-1 | `O(n·W·log k)` |

```java
// 0-1 背包：容量逆序——保证每件物品只用一次
int[] dp = new int[W + 1];
for (int i = 0; i < n; i++) {
    for (int j = W; j >= weight[i]; j--) {        // ← 逆序！
        dp[j] = Math.max(dp[j], dp[j - weight[i]] + value[i]);
    }
}

// 完全背包：容量正序——允许同一物品被反复选
for (int i = 0; i < n; i++) {
    for (int j = weight[i]; j <= W; j++) {        // ← 正序
        dp[j] = Math.max(dp[j], dp[j - weight[i]] + value[i]);
    }
}
```

**"为什么逆序"是背包最经典的考点**，理由见 [空间优化](#space-opt)。

### 模型二：LIS（最长递增子序列） {#lis}

| 解法 | 复杂度 | 思路 |
|---|---|---|
| **DP** | `O(n²)` | `dp[i]` = **以 `a[i]` 结尾**的 LIS 长度；`dp[i] = max(dp[j] + 1)`，`j < i` 且 `a[j] < a[i]` |
| **贪心 + 二分** | **`O(n log n)`** | 维护 `tails[]`：`tails[k]` = 长度为 `k+1` 的递增子序列的**最小结尾值**；用**二分**找替换位置 |

**`O(n log n)` 版本的直觉**（这个技巧值得背）：**"结尾越小，越容易接上后续元素"**。所以对每个长度，只维护"最小可能的结尾值"。`tails` 本身是递增的，所以能二分。

```java
public int lengthOfLIS(int[] a) {
    int[] tails = new int[a.length];
    int len = 0;
    for (int x : a) {
        int lo = 0, hi = len;
        while (lo < hi) {                  // 找第一个 >= x 的位置
            int mid = (lo + hi) >>> 1;
            if (tails[mid] < x) lo = mid + 1;
            else hi = mid;
        }
        tails[lo] = x;                     // 替换（或追加）
        if (lo == len) len++;
    }
    return len;
}
```

**注意 `dp` 定义的陷阱**：`dp[i]` 必须定义为"**以 `a[i]` 结尾**"，不能是"前 i 个元素里的 LIS 长度"——后者无法在转移时判断"能不能接上"（这是 DP 状态定义出错的最常见例子）。

### 模型三：两个字符串（LCS / 编辑距离） {#two-strings}

这类问题的状态天然是二维的：`dp[i][j]` = **`s1` 前 i 个字符与 `s2` 前 j 个字符**的答案。

| 问题 | 转移方程的核心 |
|---|---|
| **LCS（最长公共子序列）** | 字符相同 → `dp[i-1][j-1] + 1`；不同 → `max(dp[i-1][j], dp[i][j-1])` |
| **编辑距离** | 字符相同 → `dp[i-1][j-1]`；不同 → `1 + min(删、增、改)` 三种操作取最小 |

```java
// 编辑距离：三种操作对应三个方向
public int editDistance(String s, String t) {
    int m = s.length(), n = t.length();
    int[][] dp = new int[m + 1][n + 1];
    for (int i = 0; i <= m; i++) dp[i][0] = i;      // 全删
    for (int j = 0; j <= n; j++) dp[0][j] = j;      // 全增
    for (int i = 1; i <= m; i++) {
        for (int j = 1; j <= n; j++) {
            if (s.charAt(i - 1) == t.charAt(j - 1)) {
                dp[i][j] = dp[i - 1][j - 1];                  // 不操作
            } else {
                dp[i][j] = 1 + Math.min(dp[i - 1][j - 1],     // 替换
                              Math.min(dp[i - 1][j],          // 删除
                                       dp[i][j - 1]));        // 插入
            }
        }
    }
    return dp[m][n];
}
```

**这一族模型的工程用途很实在**：拼写纠错、DNA 比对、`git diff`（本质是最长公共子序列）、模糊搜索的相似度打分。

### 模型四：区间 DP {#interval-dp}

**特征**：状态是"**一段区间**"，转移由"**从哪个位置切开**"或"**两端怎么去**"决定。

| 问题 | 状态 | 转移 |
|---|---|---|
| **最长回文子序列** | `dp[i][j]`：区间 `[i,j]` 内最长回文子序列长度 | 两端相同 → `dp[i+1][j-1] + 2`；不同 → `max(dp[i+1][j], dp[i][j-1])` |
| **矩阵连乘（最小乘法次数）** | `dp[i][j]`：第 i~j 个矩阵相乘的最小代价 | `min(dp[i][k] + dp[k+1][j] + 合并代价)` |
| **石子合并** | 同上形态 | 同矩阵连乘 |

**区间 DP 的关键是遍历顺序**：`dp[i][j]` 依赖 `dp[i+1][j-1]`（**更短的区间**），所以必须**按区间长度从小到大**枚举：

```java
for (int len = 2; len <= n; len++) {          // ① 先枚举长度
    for (int i = 0; i + len - 1 < n; i++) {   // ② 再枚举起点
        int j = i + len - 1;                  // ③ 算出终点
        // 现在 dp[i][j] 依赖的所有更短区间都已算完
    }
}
```

**这个三层循环的顺序背下来**——写错（比如按 `i`、`j` 双增）会导致用到还没算出的状态。

### 模型五：状态压缩（集合 DP） {#bitmask-dp}

当**状态的维度是"某个集合"**且集合很小时，用一个整数的二进制位表示集合：

| 问题 | 状态 | 位运算含义 |
|---|---|---|
| **旅行商（TSP）** | `dp[mask][i]`：已访问集合为 `mask`、当前在 i 的最小代价 | `mask >> j & 1` 判断 j 是否已访问 |
| **划分 k 个等和子集** | `dp[mask]` | 枚举子集 |
| **集合覆盖** | `dp[mask]` | 按位或合并 |

**适用条件**：**元素个数 ≤ 20 左右**（因为 `2²⁰ ≈ 100 万`个状态）；再多就放不下了。

**位运算的两个常用技巧**（这类题的手感来源）：

```java
mask | (1 << i)                 // 把 i 加进集合
mask & ~(1 << i)                // 把 i 移出集合
mask & (1 << i) != 0            // 判断 i 在不在集合里
// 枚举 mask 的所有子集（总复杂度 O(3^n)）
for (int sub = mask; sub > 0; sub = (sub - 1) & mask) { ... }
```

## 四、空间优化与滚动数组 {#space-opt}

这是背包"为什么逆序"的答案所在，也是 DP 最容易写错的地方。

### 为什么 0-1 背包要逆序 {#knapsack-reverse}

一维数组 `dp[j]` 的语义是"**容量为 j 时的最大价值**"。关键问题是：**`dp[j]` 用到的 `dp[j - w]`，是"上一轮"的还是"本轮已更新过"的？**

```text
正序遍历（错误）：j 从 w 到 W
  dp[j]    = max(dp[j], dp[j - w] + v)
              ↑ 用到的是"本轮已更新过"的 dp[j-w]
  → 相当于物品 i 被用了两次以上 —— 这是"完全背包"的语义，不是 0-1！

逆序遍历（正确）：j 从 W 到 w
  dp[j]    = max(dp[j], dp[j - w] + v)
              ↑ dp[j-w] 还没被本轮碰过，还是"上一轮"的值
  → 保证物品 i 只用一次 —— 这才是 0-1 背包
```

**一句话记法**：**逆序 = 用旧值（每件一次）；正序 = 用新值（可重复拿）。**

> **这是"静默错误"的典型**：方向写反不会报错、小数据甚至可能对，但语义已经完全变了。**所以"为什么逆序"必须理解，不能背。**

### 常见的空间压缩模式 {#compression-patterns}

| 原状态 | 压缩方式 | 代价 |
|---|---|---|
| `dp[i][j]` 只依赖 `dp[i-1][*]` | **滚动数组**（两行轮换）或**直接一维倒序** | 需确认依赖方向 |
| `dp[i][j]` 依赖 `dp[i-1][j-1]`（左上角） | 一维 + **一个临时变量保存左上角旧值** | 容易写错，需仔细 |
| 区间 DP 依赖更短区间 | **按长度枚举**，天然只需保留上一层 | 顺序必须正确 |

## 五、回溯：为什么它是 DP 的"上一站" {#backtracking}

**回溯的本质是"带撤销的暴力搜索"**。它和 DP 的关系是：**同一个问题，去掉"重叠子问题"这个前提，DP 就退回成回溯。**

```text
决策树（爬楼梯，每次选 1 或 2）：

                    start
                   /      \
                1           2
               / \         / \
              1   2       1   2
             ...  ...    ...  ...
   同一层的节点被反复计算 → 这就是"重叠子问题"
   DP 用一张表把它压成 O(n)；回溯则老老实实展开成 O(2ⁿ)
```

### 两个通用模板 {#backtracking-templates}

```java
// 模板一：组合 / 子集（元素不可重复用）——用 start 控制"只能往右选"，天然去重
void backtrack(int[] nums, int start, List<Integer> path, List<List<Integer>> res) {
    res.add(new ArrayList<>(path));               // 每个节点都是一个合法答案（子集问题）
    for (int i = start; i < nums.length; i++) {
        if (i > start && nums[i] == nums[i - 1]) continue;   // 跳过同层重复（数组需先排序）
        path.add(nums[i]);
        backtrack(nums, i + 1, path, res);        // i+1：不能重复用
        path.remove(path.size() - 1);             // 撤销
    }
}

// 模板二：排列（元素可重复用，靠 used 数组控制）——交换法或 used 标记
void permute(int[] nums, boolean[] used, List<Integer> path, List<List<Integer>> res) {
    if (path.size() == nums.length) { res.add(new ArrayList<>(path)); return; }
    for (int i = 0; i < nums.length; i++) {
        if (used[i]) continue;
        used[i] = true;
        path.add(nums[i]);
        permute(nums, used, path, res);
        path.remove(path.size() - 1);
        used[i] = false;
    }
}
```

**两个模板的区别是"要不要 `start`"**：

| | 组合 / 子集 | 排列 |
|---|---|---|
| 控制方式 | **`start` 参数**（只能往右选） | **`used` 数组**（任意位置选未用过的） |
| 为什么 | 避免"选过的又选一次"和"顺序不同的重复解" | 顺序有意义，所以每个位置都要尝试所有未用元素 |

### 剪枝：把指数降到可用 {#pruning}

**剪枝是回溯唯一的优化手段**（因为回溯的复杂度上界是指数）。三个常用剪枝：

| 剪枝 | 做法 | 例 |
|---|---|---|
| **可行性剪枝** | 当前路径已不可能满足约束 → 提前返回 | 组合求和：`sum > target` 就返回 |
| **最优性剪枝** | 当前代价已超过已知最优 → 提前返回 | 求最小代价时，`cost >= best` 就剪 |
| **顺序剪枝** | 排序后，一旦不满足，后面的也不用试 | 组合求和：排序后 `sum + nums[i] > target` 即可 `break` |

> **面试判断标准**：被问回溯题时，**能主动说出"这里可以剪枝"并给出依据**，比写出完整代码更被认可——因为它表明你知道"暴力搜索为什么能变成可用的算法"。

## 六、使用场景与面试问答 {#interview}

### 6.1 按场景跳转

### 6.2 概念级速查

| 问题 | 一句话答案 | 详见 |
|---|---|---|
| DP 要满足哪两个前提？ | **最优子结构**（全局最优含子问题最优）+ **无后效性**（当前状态不受未来决策影响）；少了任何一个只能搜索 | [#paradigms](#paradigms) |
| DP 和分治的区别？ | 分治的子问题**相互独立**；DP 的子问题**相互重叠**，所以需要缓存/表格 | [#paradigms](#paradigms) |
| DP 和贪心的区别？ | 贪心**每步只保留一个选择、不回头**；DP **枚举所有选择**并比较 | [#paradigms](#paradigms) |
| "找零钱"为什么不能用贪心？ | 面额 `[1,3,4]` 凑 6：贪心得 3 张、最优是 2 张（`3+3`）——**局部最优损害了后续选择** | [#greedy-counterexamples](#greedy-counterexamples) |
| 怎么判断贪心是否可行？ | **找反例**。找到即不可行；**找不到不等于正确**，需要交换论证之类的证明 | [#greedy-counterexamples](#greedy-counterexamples) |
| 建议先写记忆化还是递推？ | **先写记忆化**（思路直接、只算用得到的状态），正确后再改递推做空间优化 | [#top-down-vs-bottom-up](#top-down-vs-bottom-up) |
| 0-1 背包为什么容量要逆序？ | 逆序时 `dp[j-w]` 还是"上一轮"的旧值 → **每件物品只用一次**；正序会用本轮新值 → 变成完全背包 | [#knapsack-reverse](#knapsack-reverse) |
| LIS 的 `O(n log n)` 解法靠什么？ | **`tails[k]` = 长度 k+1 的递增子序列的最小结尾值**（越小越容易接上后续），配合二分 | [#lis](#lis) |
| LIS 的 `dp[i]` 该怎么定义？ | 必须定义为"**以 `a[i]` 结尾**"的 LIS 长度；定义成"前 i 个元素"无法在转移时判断能否接上 | [#lis](#lis) |
| 编辑距离的三种操作对应什么？ | 替换 → `dp[i-1][j-1]`、删除 → `dp[i-1][j]`、插入 → `dp[i][j-1]`；取三者最小值 +1 | [#two-strings](#two-strings) |
| `git diff` 用的是什么算法？ | **最长公共子序列（LCS）**——找两版文件的最大公共部分，剩下的就是增删 | [#two-strings](#two-strings) |
| 区间 DP 的遍历顺序为什么特殊？ | `dp[i][j]` 依赖**更短区间**，所以必须**按区间长度从小到大**枚举 | [#interval-dp](#interval-dp) |
| 状态压缩 DP 的适用边界？ | 状态是"集合"且元素数 **≤ 20 左右**（状态数 `2ⁿ`）；再多内存放不下 | [#bitmask-dp](#bitmask-dp) |
| 回溯和 DP 是什么关系？ | **回溯 = 去掉"重叠子问题"前提的 DP**：同一问题不带记忆化搜索就是指数级回溯 | [#backtracking](#backtracking) |
| 组合和排列模板的区别？ | **组合/子集用 `start` 参数**（只能往右选、天然去重）；**排列用 `used` 数组**（顺序有意义） | [#backtracking-templates](#backtracking-templates) |
| 回溯怎么优化？ | **可行性剪枝**（约束不满足提前返回）、**最优性剪枝**（已超出已知最优）、**顺序剪枝**（排序后提前 `break`） | [#pruning](#pruning) |

### 6.3 一句话总结

> **这一篇要带走的不是任何一道题的解，而是三个判断：**
> **① 有重叠子问题、能定义状态 → DP；**
> **② 能证明局部最优即全局最优 → 贪心；**
> **③ 两者都不行 → 回溯 + 剪枝。**
> **而 DP 的功夫全在第一步"状态是什么"——状态定义是 DP 的全部，转移方程只是它的推论。**
