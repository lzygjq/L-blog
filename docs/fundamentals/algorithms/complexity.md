# 复杂度分析

> 下一篇：[线性结构：数组、链表、栈、队列](/fundamentals/algorithms/linear)

这一篇不教算法，教的是**衡量算法的语言**。后面六篇里每一句"这个更快""那个更划算"，依据都在这一篇。

**先把结论放前面**：

1. **复杂度描述的是增长趋势，不是耗时**。`O(3n + 3)` 与 `O(n)` 是同一条曲线——所以在 n 足够大时，低阶项、系数、常量全部可以扔掉。
2. **只有三种复杂度值得记**：`O(1)`、`O(log n)`、`O(n)`、`O(n log n)`——再往上的 `O(n²)`、`O(2ⁿ)` 是**需要被优化的信号**，不是可以接受的选择。
3. **面试里真正拉开差距的是「均摊」和「最坏」**。`ArrayList` 尾部插入是 `O(1)` 均摊但最坏 `O(n)`；快排平均 `O(n log n)` 但最坏 `O(n²)`。能说清这两个的区别，比背表格有用。
4. **`O(1)` 不等于快**。哈希表查找是 `O(1)`，但常数因子可能是数组下标的几十倍。复杂度只管趋势，不管绝对值。

## 一、到底在衡量什么 {#why-complexity}

同一段业务逻辑，换个写法性能能差一个数量级。复杂度分析解决两件事：

- **写代码时**：知道自己选的写法在数据量增长后会怎么劣化；
- **读代码时**：能判断别人的实现好不好，而不是只能凭感觉。

它衡量的是**执行时间（或占用空间）随数据规模增长的变化趋势**。不纠结"这段代码实际跑了几毫秒"——那受机器、JIT、GC 影响太大，横向比较没有意义。

举个具体例子：

```java
// 写法 A：单层循环
public int sum(int n) {
    int sum = 0;
    for (int i = 1; i <= n; i++) {
        sum = sum + i;          // 执行 n 次
    }
    return sum;
}

// 写法 B：双重循环
public int sum2(int n) {
    int sum = 0;
    for (int i = 1; i <= n; i++) {
        for (int j = 1; j <= n; j++) {
            sum = sum + i * j;  // 执行 n² 次
        }
    }
    return sum;
}
```

n = 100 时，B 执行 10000 次，可能只慢几毫秒；n = 100 万时，B 要执行 10¹² 次——不是慢几倍的问题，是根本跑不完。**复杂度分析的价值就在于：它能在还没跑之前就告诉你这件事。**

## 二、大 O、Ω、Θ：三个记号的分工 {#notation}

日常说"这个算法是 `O(n)`"，严格讲是在说**上界**。三个记号各有分工：

| 记号 | 含义 | 直觉 | 常见误区 |
|---|---|---|---|
| **`O(f(n))`** | **上界**：增长不会超过 f(n) | "最快也就这样了" | 最容易和 Θ 混用 |
| **`Ω(f(n))`** | **下界**：增长不会低于 f(n) | "再快也快不过这样" | 很少单独使用 |
| **`Θ(f(n))`** | **紧确界**：上下界都是 f(n) | "就是这个量级" | 工程里说的 O 其实多半是 Θ |

**工程语境里 99% 的场合，说的 `O` 其实指的是 `Θ`**——即"这个算法就是这个量级"。因为只说上界太弱了：冒泡排序也可以写成 `O(n³)`（上界宽松但没意义）。所以本文之后一律按"紧确界"理解 `O`。

**唯一的例外是"最坏情况"的表述**。说"快排是 `O(n log n)`"时，严格说应该是"平均 `O(n log n)`，最坏 `O(n²)`"——此时 `O` 是真的在说上界。

### 化简规则 {#simplify}

三条规则，从大到小：

1. **只保留最高阶**：`O(n² + n)` → `O(n²)`
2. **去掉系数**：`O(3n)` → `O(n)`
3. **去掉常量**：`O(3n + 1000)` → `O(n)`

> **为什么系数可以去掉？** 因为复杂度关心的是"n 翻倍时耗时怎么变"。`3n` 和 `n` 都是"n 翻倍、耗时翻倍"，是同一条曲线。**但如果两个算法的量级相同**（都是 `O(n)`），系数就成了唯一区别——这时复杂度分析就帮不上忙了，得实测。这条边界要清楚：**复杂度不是性能的全部。**

常对幂指阶（常数 → 对数 → 幂 → 指数 → 阶乘），性能从高到低：

| 量级 | 典型形态 | n = 100 万时的量级感 |
|---|---|---|
| `O(1)` | 哈希查找、数组下标 | 1 次操作 |
| `O(log n)` | 二分查找、平衡树 | 约 20 次 |
| `O(n)` | 一次遍历 | 100 万次 |
| `O(n log n)` | 好排序的下界 | 约 2000 万次 |
| `O(n²)` | 双重循环 | 10¹² 次（不可接受） |
| `O(2ⁿ)` | 无记忆化的递归 | 天文数字 |

**判读代码量级的三条口诀**（比背表格管用）：

- **看循环变量的变化方式**：`i++` 是线性，`i *= 2` 是对数，`i /= 2` 也是对数；
- **看循环层数**：两层独立的 `n` 循环就是 `n²`；**但如果内层依赖外层**（如 `for i: for j from i to n`），实际是 `n(n+1)/2`，量级仍是 `n²`；
- **看递归的分叉数**：一次分两支且不做记忆化 → 指数级；分两支但规模减半 → `O(n log n)`（如归并）。

## 三、主定理：一眼看出递归的复杂度 {#master-theorem}

递归算法套公式就能算，不用画树。对形如

```text
T(n) = a · T(n / b) + O(n^d)
```

（a ≥ 1 个子问题，每个规模是 n/b，合并代价 `O(n^d)`）的递归式，比较 `log_b(a)` 与 `d`：

| 情况 | 条件 | 结果 | 直觉 |
|---|---|---|---|
| 1 | `log_b(a) > d` | `T(n) = O(n^(log_b a))` | **叶子比合并贵**，成本在递归底层 |
| 2 | `log_b(a) = d` | `T(n) = O(n^d · log n)` | **每层代价相同**，共 log n 层 |
| 3 | `log_b(a) < d` | `T(n) = O(n^d)` | **合并比叶子贵**，成本在根节点 |

拿最常见的三个算法验一遍：

| 算法 | 递归式 | `log_b a` vs `d` | 结论 |
|---|---|---|---|
| 归并排序 | `T(n) = 2T(n/2) + O(n)` | `log₂2 = 1 = d` → 情况 2 | `O(n log n)` ✅ |
| 二分查找 | `T(n) = T(n/2) + O(1)` | `log₂1 = 0 < d=0`？不，`d=0`，`0 = 0` → 情况 2 | `O(log n)` ✅ |
| 二叉树遍历 | `T(n) = 2T(n/2) + O(1)` | `log₂2 = 1 > d=0` → 情况 1 | `O(n)` ✅ |

**不用背主定理也能算**：画递归树，数"每层总代价 × 层数"。归并排序每层代价都是 `O(n)`，共 `log n` 层，所以 `O(n log n)`——这正是主定理情况 2 的直觉。

## 四、均摊分析：为什么 `ArrayList` 尾部插入是 O(1) {#amortized}

这是复杂度分析里**最容易答错、也最能区分水平**的一块。

`ArrayList.add()` 在容量够时是 `O(1)`（直接写数组末尾），但容量不够时要**扩容 + 复制整个数组**，是 `O(n)`。那 add 到底是 `O(1)` 还是 `O(n)`？

**答案是：单次调用最坏 `O(n)`，但均摊（amortized）`O(1)`。**

关键在于扩容的**倍增策略**。假设从 1 开始、每次容量不够就翻倍，插入 n 个元素的总代价：

```text
扩容点：1 → 2 → 4 → 8 → ... → n
复制代价：1 + 2 + 4 + ... + n/2 = n - 1  ≈ O(n)
```

**n 次插入总代价是 `O(n)`，均摊到每次就是 `O(1)`**。这就是均摊分析（amortized analysis）：不保证每一次都快，但保证"连续 m 次操作的总代价 / m"有上界。

> **均摊 ≠ 平均**。平均复杂度是对**输入分布**求期望（需要假设输入随机）；均摊复杂度是**对最坏的操作序列**做算术，不需要任何概率假设。这是两者最本质的区别，面试里能主动说出这点会很加分。

### 为什么是 1.5 倍而不是 2 倍 {#growth-factor}

Java 的 `ArrayList` 用的是 **1.5 倍**（`newCapacity = oldCapacity + (oldCapacity >> 1)`），`HashMap` 用的是 **2 倍**（容量必须是 2 的幂，方便用位运算代替取模）。两种都能保证均摊 `O(1)`，差别在**空间利用率与内存回收**：

| 因子 | 空间浪费 | 能否复用旧内存块 | 说明 |
|---|---|---|---|
| **2 倍** | 最高浪费 100%（用了 3 个元素却占了 4 个位置） | **不能**：新块永远比旧块大，旧块无法被后续分配复用 | 均摊代价更低（复制次数更少） |
| **1.5 倍** | 最高浪费 50% | **可能**：多次扩容后出现的空洞有机会被复用 | C++ `std::vector` 常见选择，Java `ArrayList` 采用 |

**这就是"复杂度相同但工程取舍不同"的典型例子**——两者都是均摊 `O(1)`，选哪个要看你是更在意内存还是更在意复制开销。

## 五、空间复杂度：常被忽略的那一半 {#space}

空间复杂度全称**渐进空间复杂度**，衡量的是**额外占用的存储空间**（不含输入本身）随规模的增长关系。

```java
public void print(int n) {              // O(n)：申请了长度为 n 的数组
    int[] a = new int[n];
    for (int i = 0; i < n; i++) {
        a[i] = i * i;
    }
}
```

常见只有 `O(1)`、`O(n)`、`O(n²)` 三档，所以比时间复杂度好分析。但有两个坑：

**坑一：递归的栈深度要算进去。** 递归算法的空间复杂度 = **递归深度 × 每层帧大小**。归并排序的空间是 `O(n)`（辅助数组）**加上** `O(log n)`（递归栈）；快排平均 `O(log n)`（栈）——**这是快排相较归并的优势之一**。但快排最坏退化成 `O(n)` 栈深度，这正是 JDK 在递归过深时切换到堆排序的原因（见 [排序](/fundamentals/algorithms/sorting#jdk-impl)）。

**坑二：「原地」不等于零额外空间。** 快排叫"原地排序"，但它需要 `O(log n)` 的栈；堆排序才是真正 `O(1)` 额外空间的原地排序。**"原地"的准确含义是"额外空间是 `O(1)` 或 `O(log n)`，不随输入线性增长"。**

## 六、几个高频误判 {#pitfalls}

复杂度分析出错，多半不是公式用错，而是**把某个操作的隐藏代价漏算了**。

| 代码 | 直觉判断 | 实际 | 为什么 |
|---|---|---|---|
| `for` 循环里 `s += str` | `O(n)` | **`O(n²)`** | Java 的 `String` 不可变，每次 `+=` 都新建对象并复制全部内容 |
| `list.contains(x)` 在循环里 | `O(n)` | **`O(n²)`** | 外层循环 `n` × 内层 `O(n)` 查找 |
| `map.get(k)` | `O(1)` | **平均 `O(1)`**，最坏 `O(n)` | 哈希冲突全撞一个桶时退化为链表遍历（JDK 8 起树化为 `O(log n)`） |
| `arr[i]` 在 `LinkedList` 上 | `O(1)` | **`O(n)`** | `LinkedList` 没有随机访问，`get(i)` 要顺着指针走 i 步 |
| `String.substring` | `O(n)` | **`O(k)`**，k 为子串长度 | JDK 7 起改为**拷贝**（JDK 6 是共享底层数组的视图，`O(1)` 但会造成内存泄漏） |
| 快排排序已排序数组 | `O(n log n)` | **`O(n²)`** | 固定选端点做 pivot 时，每次划分都极不平衡 |

**这张表的方法论意义**：判断复杂度时，先问"**这个 API 内部做了什么**"（是否复制、是否遍历、是否分配），再看外层循环。Java 里那些"看起来像 `O(1)` 实际是 `O(n)`"的 API，几乎都是因为**内部偷偷做了复制或遍历**。

### 7.2 概念级速查

| 问题 | 一句话答案 | 详见 |
|---|---|---|
| 什么是时间复杂度？ | 表示算法**执行时间随数据规模增长的趋势**，不是实际耗时；低阶项、系数、常量都可忽略 | [#why-complexity](#why-complexity) |
| `O`、`Ω`、`Θ` 有什么区别？ | `O` 是上界、`Ω` 是下界、`Θ` 是紧确界；工程语境下说 `O` 多半指 `Θ` | [#notation](#notation) |
| 常见复杂度有哪些？ | `O(1)` < `O(log n)` < `O(n)` < `O(n log n)` < `O(n²)` < `O(2ⁿ)`，速记「常对幂指阶」 | [#simplify](#simplify) |
| 主定理怎么用？ | `T(n) = aT(n/b) + O(n^d)`，比较 `log_b a` 与 `d`：大于取左、等于乘 log、小于取右 | [#master-theorem](#master-theorem) |
| 均摊复杂度和平均复杂度是一回事吗？ | **不是**。均摊是对**最坏操作序列**做算术（无需概率假设），平均是对**输入分布**求期望 | [#amortized](#amortized) |
| `ArrayList.add` 是 `O(1)` 吗？ | **均摊 `O(1)`、单次最坏 `O(n)`**。扩容的倍增策略让 n 次插入总代价为 `O(n)` | [#amortized](#amortized) |
| 为什么 `ArrayList` 扩容 1.5 倍而 `HashMap` 2 倍？ | 都能保证均摊 `O(1)`；1.5 倍**空间浪费更小且有机会复用旧内存块**，2 倍是 `HashMap` 为了用位运算取模 | [#growth-factor](#growth-factor) |
| 递归算法的空间复杂度怎么算？ | **递归深度 × 每层帧大小**；归并排序是 `O(n)`（辅助数组）而非 `O(log n)` | [#space](#space) |
| 快排是原地排序，那它零额外空间吗？ | 不是，需要 `O(log n)` 栈；**真正 `O(1)` 额外空间的原地排序是堆排序** | [#space](#space) |
| 循环里 `s += str` 是 `O(n)` 吗？ | 不是，是 **`O(n²)`**——`String` 不可变，每次拼接都复制全部内容 | [#pitfalls](#pitfalls) |

### 7.3 一句话总结

> **复杂度分析的目的不是算出一个公式，而是让你在写下 `for` 循环之前就知道，这段代码在数据量涨十倍之后还能不能用。**
