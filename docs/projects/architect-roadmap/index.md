# 架构师知识路线图

> 一句话总览：架构师成长分五步——**地基**（计算机基础）→ **骨架**（分布式核心）→ **核心**（架构设计能力）→ **进阶**（工程效能与云原生）→ **顶层**（架构师思维）。前两步决定能不能干活，第三步决定值不值架构师的价，第四五步决定能走多远。

## 五阶段总览

| 阶段 | 主题 | 核心内容 | 性质 |
|---|---|---|---|
| 阶段1 | 计算机基础与语言 | 操作系统、网络、算法、JVM、并发、MySQL 原理 | 地基 |
| 阶段2 | 分布式核心 | CAP/BASE、Redis、MQ、微服务治理、分布式事务、分库分表 | 骨架 |
| 阶段3 | 架构设计能力 | 高可用、高性能、安全、可观测性、DDD | 核心 |
| 阶段4 | 工程效能与云原生 | CI/CD、灰度发布、K8s、服务网格、大数据 | 进阶 |
| 阶段5 | 架构师思维 | 技术权衡、架构演进、技术规划、业务建模 | 顶层 |

## 阶段1 · 计算机基础与语言（地基）

| 模块 | 要掌握到什么程度 |
|---|---|
| 操作系统 | 进程线程、内存管理、文件系统、Linux 常用命令、IO 模型（BIO/NIO/AIO/多路复用） |
| 网络 | TCP 三次握手/四次挥手、HTTP/HTTPS、DNS、负载均衡原理 |
| 数据结构与算法 | 常用数据结构 + 排序/查找，能分析复杂度（面试必考） |
| JVM | 内存模型、类加载、GC 算法与调优、线上排查（会看 dump 文件） |
| Java 并发 | 锁、线程池、AQS、volatile、CAS、并发工具类（源码级理解） |
| MySQL | 索引（B+树）、事务隔离级别、MVCC、锁机制、慢查询优化 |

**投入建议**：这一层的分水岭在 MySQL 底层原理和 JVM 线上调优——目标是「能实战排查」，而不是背概念。

## 阶段2 · 分布式核心（骨架）

| 模块 | 核心内容 | 本站对应 |
|---|---|---|
| 分布式理论 | CAP 定理、BASE 理论、一致性协议（Paxos/Raft）、分布式 ID | [CAP 与 BASE](/java/spring/spring-cloud/cap-base)（已成篇；Paxos/Raft、分布式 ID 仍缺） |
| Redis | 数据结构、持久化、主从哨兵集群、缓存三大问题、分布式锁 | [Redis 板块](/database/redis/)（已成篇 10 篇） |
| 消息队列 | Kafka/RocketMQ 原理、消息可靠性、幂等、顺序消息、事务消息 | [消息队列板块](/middleware/) |
| 微服务治理 | 注册中心（Nacos）、配置中心、网关、熔断降级、链路追踪 | [Spring Cloud](/java/spring/spring-cloud/)（已成篇 5 篇） |
| 分布式事务 | 2PC/XA、TCC、SAGA、Seata、本地消息表 | [分布式事务](/java/spring/spring-cloud/transaction)（已成篇） |
| 接口幂等 | 重复提交、消息重投、去重方案选型 | [接口幂等](/java/spring/spring-cloud/idempotency)（已成篇） |
| 任务调度 | 集群任务去重、分片并行、失败处理 | [分布式任务调度](/java/spring/spring-cloud/scheduling)（已成篇） |
| 分库分表 | ShardingSphere、数据迁移、读写分离 | [分库分表](/database/sharding/) |

**面试深水区**：分布式事务完整方案（TCC/SAGA）和一致性协议原理（Paxos/Raft）是架构师面试的高频深水区，值得优先啃。

## 阶段3 · 架构设计能力（核心）

| 模块 | 核心内容 |
|---|---|
| 高可用 | 多机房容灾、同城双活、限流熔断降级、故障演练 |
| 高性能 | 性能调优、全链路压测、容量规划、缓存/异步/削峰 |
| 安全 | 认证授权（OAuth2/SSO）、数据加密脱敏、防刷防注入、等保合规 |
| 可观测性 | Prometheus 监控、SkyWalking 链路追踪、ELK 日志、告警体系 |
| 方法论 | DDD 领域驱动设计、架构风格对比、架构演进 |

**为什么是核心**：这一层是架构师与高级开发的本质区别——高可用容灾与性能调优实战最能拉开差距，架构师的核心价值就体现在这一层。参考落地视角见[项目实战](/projects/)下的真实难点复盘。

## 阶段4 · 工程效能与云原生（进阶）

| 模块 | 核心内容 | 本站对应 |
|---|---|---|
| DevOps | CI/CD 流水线（Jenkins/GitLab CI）、灰度发布、蓝绿部署 | [CI/CD](/cloud-native/cicd/) |
| 云原生 | Docker、Kubernetes、服务网格（Istio）、弹性伸缩 | [云原生板块](/cloud-native/) |
| 大数据 | 数仓分层、实时计算（Flink）、OLAP（Doris/ClickHouse） | [数据仓库板块](/bigdata/) |
| 多机房架构 | 双活、异地灾备、数据同步 | 规划中 |

**节奏建议**：云原生与 DevOps 是加分项，优先级低于阶段3——先建立架构设计能力，再补工程效率面。

## 阶段5 · 架构师思维（顶层）

| 能力 | 说明 |
|---|---|
| Trade-off 权衡 | 架构的本质是取舍，能讲清「为什么这么选、放弃了什么」 |
| 架构演进 | 从单体 → 微服务 → 云原生的演进路径判断 |
| 技术规划 | 技术选型、技术债管理、技术路线制定 |
| 方案评审 | 主导技术评审、说服团队、控制技术风险 |
| 业务理解 | 把业务需求翻译成技术架构，领域建模 |

这一层不是「学」出来的，是前四层积累后的自然跃迁。面试架构师岗时，考的就是能否站在这个高度做决策。

## 学习优先级建议

| 优先级 | 方向 | 理由 |
|---|---|---|
| 🔴 第一优先 | 阶段3 高可用 + 性能调优 | 架构师核心差距，最值得投入 |
| 🔴 第二优先 | 阶段2 分布式事务 + 一致性协议 | 面试高频深水区 |
| 🟡 第三优先 | 阶段4 云原生 + DevOps | 加分项，不急于一时 |
| 🟢 持续投入 | 阶段5 架构师思维 | 随前几层自然成长 |

**总结**：路线是「地基 → 骨架 → 核心 → 进阶 → 顶层」。地基和骨架打好后，最该啃的是阶段3 的架构设计能力——高可用、性能、安全、可观测性四块，这是从开发到架构师最关键的一跃。
