## 1. 目标与验收指标

关键路径：提交（写）+ 待办列表 / 进度统计（读）。读写比按 20:1 混压，禁止只压写。

| 指标 | 设计目标 | 备注 |
|---|---|---|
| 峰值提交 | 20 TPS，瞬时可到 30 | 分批放号把集中系数压到 ~5 之后的推导；分批**尚未落地** |
| 峰值查询 | 约 400 QPS | 峰值提交 × 20 |
| 受理单写入 | P99 < 100ms | 同步段 |
| 异步落库 | P95 < 3s，P99 < 30s | 队列消费 |
| 全局限流 | 1,200 QPS | 峰值读写 + 30% 余量；**压完才能写进承诺** |

错误率、资源水位（CPU / 连接池 / 行锁等待 / 队列深度）按[压测方法](/projects/toolkit/perf-report/)八要素记。本页不编分档实测表。

## 2. 场景与流量模型

- 接口组合：提交、列表、详情、进度统计同时在。
- 分布：20% 部门承担 80% 提交。均匀分布压不出热点。
- 数据量：表单与历史周期到接近设计量级（专题按约 6 万人规模推导）。1 万行表上的结论在 18 万行上不可用。
