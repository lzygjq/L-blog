## 1. 目标与验收指标

压测要拿到三样东西：真实容量上限、调参依据、故障时行为基线。不是「跑个报告」。

| 项 | 设计目标 | 现状 |
|---|---|---|
| 集团型画像整体峰值 | 3,000–8,000 QPS 下 P99 < 1s | 估算 |
| 缴费链路 | 2,000 QPS 下滑峰有效，库不被打穿 | 估算 |
| 1.5 倍峰值 | 允许排队，不允许雪崩 | 未验证 |
| 压测停止后 | 能自动恢复 | 未验证 |
| 错误率 | < 0.1%（目标 QPS 下） | 未验证 |

**两个 QPS 不是同一口径**：场景拆分表 vs 平台整体画像。对外必须标明，禁止把两个数字并进一句 SLA。

资金链路验收是「进来的都正确」，不是「尽量都进去」。资金不能降级放行。

## 2. 场景与流量模型

必压、且必须混合：

1. 缴费（核心资金）
2. 团购抢购（瞬时并发）
3. 全量推送（消息积压极限）
4. 门禁早高峰（高频短请求）
5. 大报表（慢 SQL 与缓存穿透）

流量按租户 / 小区长尾分布。固定参数压不出热点 Key。
