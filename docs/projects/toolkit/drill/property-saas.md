# 模拟盘 · 物业 SaaS

闭卷。规则见[模拟盘导览](/projects/toolkit/drill/#rules)。本页**不给选型**。

## 题干 {#stem}

面向物业公司的多租户 SaaS。租户日常要：算钱、收钱、管人、管门、卖东西。租户数量多，**规模差一个数量级**（几个小区 vs 上千个项目）。账单按月批量生成，金额不能错。门禁是硬件 + 实时 + 弱网。出账和催缴挤在月初。报表要多维下钻和长期留存。一套代码、一套部署，被很多租户共用。

五篇专题是一条自下而上的链，**按 1→5 写**。

---

## 第一题 · 业务与数据 {#q-core}

1. 先把「业务特点」翻成架构约束。跳过这一步直接点组件名，后面的题按零分处理。
2. 账单金额、并发改账单、支付回调，各用什么保证「不能错」？资金链路上能不能降级成「先近似正确」？
3. 出账任务在多副本下会跑两次。只靠分布式锁够不够？锁之外还要有什么（幂等 / 分片 / 互斥）？
4. 门禁弱网时，正确性边界放在云上还是设备上？离线开了门，回来怎么补？
5. 团购库存不超卖：缓存预减、队列、回补，各防哪一种失败？超卖和少卖你先保住哪一个？
6. 分片键现在就要定吗？过早引入分片中间件，你会用什么重审条件拦住自己？

---

## 第二题 · 工程与部署 {#q-eng}

拆成多个服务之后，横切（鉴权、租户、幂等、缓存、消息、日志）开始各写各的。

1. 每个服务自己引依赖 / 每个能力一个 starter / 收成一个框架包，三种各付什么。当前约束下你选哪一种？漏引一个能力静默失效，和多带几个用不到的包，哪件更贵？
2. 聚合之后的四条代价，你准备用什么缓解？框架模块能不能依赖业务模块？
3. 「多租户」是是非题还是分档题？至少三档。小租户进来和大租户提合规，迁移路径在数据模型上要先埋什么，否则永远升不上去？
4. 租户过滤能不能靠「开发记得在 WHERE 里加」？漏一个横切点（缓存、消息、文件、定时任务）会出什么事故？
5. 单体 → 容器 → 编排，是不是必须等微服务齐活才走部署线？[层账](/projects/architecture-evolution/ledger/#sys-b)里应用档和部署档为什么可以不是同一格？

## 第三题 · 分析负载 {#q-dw}

报表把在线库打慢。有人默认「大数据 = 某一套全家桶」。团队没有专职数据平台组。业务要分钟级可查，不是 T+1。历史还要留年。

1. 分析要不要从在线库迁走？迁走之后在线库还留什么？
2. 列出分析引擎、历史介质、同步方式、变更分发的候选。每一行写**否决理由**，不要只写选中项。
3. 定时轮询业务库、应用双写进仓，各死在哪？
4. 冷热分层时，「先删源再发现目标不全」为什么是事故高发点？正确顺序是哪三步？
5. 引入一个组件前，你用哪句话区分「必需」和「可能用到」？

---

## 第四题 · 容量 {#q-cap}

1. 为什么不能用「日均请求 ÷ 86400」配峰值？集中系数动一格，容量会差多少倍（数量级即可，标估算）？
2. 限流、熔断、降级谁在最前？资金链路为什么通常只能排队不能降级？
3. 压测要拿到哪三样东西才算证据？只压单接口、数据量不够、不看中间件，各会得出什么假结论？
4. 限流阈值什么时候才能写进对外承诺？
5. 打开案例前先写：本页所有 QPS 在你的答案里应标什么状态？

---

## 第五题 · 交付 {#q-ship}

1. 四种发布策略各买什么、各在数据库变更时失效在哪？
2. 扩展—迁移—收缩为什么不能合成一步？
3. 账号注销时主库 `DELETE` 之后，副本还可能在哪几类地方？（至少备份、仓、日志、缓存、搜索、文件。）
4. 这一题里哪些必须标「仅方案」，即使设计已经写完？
