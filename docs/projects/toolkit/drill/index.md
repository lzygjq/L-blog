# 闭卷模拟盘

> **这一页是练习，不是新知识。** [成长 L3 架构师](/projects/architect-roadmap/architect/)已经写过：这一级过不过，取决于有没有独立推演过一个完整系统。下面两份卷子把案例的**约束**给你，把**选型藏起来**。

## 一、规则 {#rules}

1. **先写后看。** 打开卷子时不要另开专题页。写不出来就空着，空着的格子就是还没内化的判断。
2. 每一问按 ADR 五节的骨架答，不必写成正式 ADR：**约束 → 至少三个备选 → 选哪个 → 否决理由（代价 / 风险 / 数据）→ 重审条件 → 哪些只是方案尚未验证**。
3. 估算必须标「（估算，待验证）」。禁止编生产 TPS。
4. 对照时只许核对自己写过的格子。对得上不是目的；**写下的否决理由和案例是不是同一件事**才是。
5. 已经读过案例也先当闭卷写。能默出来的才是判断，翻出来的是阅读记忆。

对照入口在每份卷子**最末一节**，中间不要往下翻去找答案——那里没有答案，只有链接。

写完需要落成站点证据时：决策 → [ADR](/projects/toolkit/adr/)；容量假设 → [压测口径](/projects/toolkit/perf-report/)；结构 → [架构图](/projects/toolkit/arch-diagram/)。两个案例**没有**可公开发布的故障时间线，本站不编复盘；真出事用[故障复盘](/projects/toolkit/postmortem/)的模板。

## 二、两份卷子 {#exams}

| 卷子 | 练什么 | 建议用时 |
|---|---|---|
| [绩效系统 · 四段链路](/projects/toolkit/drill/perf-system) | 单点深挖：同步 / 洪峰 / 推送 / 预计算，每一段都是「两件冲突的目标怎么拆开」 | 一次写一段，四段不必同一天 |
| [物业 SaaS · 演进与多租户](/projects/toolkit/drill/property-saas) | 系统形态：隔离分档、分析外移、工程收敛、容量怎么推 | 一次写完「约束地图」，再逐题 |

层账不在卷子里。推演前可以先打开[层账](/projects/architecture-evolution/ledger/)看甲、乙现在各层在哪一档，但不要带着「标准答案档位」去填卷子。
