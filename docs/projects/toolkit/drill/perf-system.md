# 模拟盘 · 绩效系统

闭卷。规则见[模拟盘导览](/projects/toolkit/drill/#rules)。本页**不给选型**。

## 题干 {#stem}

面向约 6 万人规模组织的绩效系统（设计目标，非生产实测）。一个考核周期里：定目标、填报、多级审批、算分、出报表。组织与考核单元的权威数据在**集团统一的 HR 系统**里，绩效这边拿不到库。填报有**硬截止时间**。审批人经常不在电脑前。结算期同一张汇总会被很多人反复打开。封板前数据会改（驳回重填、调权重）。分数和薪酬相关。

四个专题对应一条时间线，**按 1→4 写**，后面的题用到前面的口径。

---

## 第一段 · 数据进来 {#q-sync}

HR 只暴露接口，不暴露数据库。考核范围一旦周期开始就不能跟着组织调整漂移。打开填报页、算考核单元是**高频读**。组织调整经常是「整块部门搬家」。树深度通常不超过 6。

1. 同步要不要落地一份？不落地行不行？判据是新鲜度还是别的？
2. 列出至少四种把数据弄过来的办法。当前约束下哪种直接不可选？为什么「不可选」有时不是技术不行？
3. 不要全量、只靠增量，会把正确性押在什么假设上？
4. 树怎么存？读写模式分别是什么？至少否决两种模型，否决理由必须落到「组织调整期」会怎样。
5. 全量更新时，读请求不能看到半棵树。你怎么切？为什么「先删后写」不行？
6. 这一段里哪些你会标「仅方案 / 尚未验证」？

---

## 第二段 · 数据写入 {#q-fill}

全员填报挤在窗口两端。截止时间不可协商。峰值相对均值可以到几十倍。用户会刷新、开多标签、弱网重发、甚至直接打接口。有人会以为「主键打散就能提高写入」。

1. 峰值能不能用「窗口期总量 ÷ 窗口秒数」算？差在哪一个系数？
2. 列出至少三条削峰路。**这一问的死线是：你能不能拒绝请求？** 判据是什么（和秒杀比）？
3. 校验和落库谁同步、谁异步？「提交即成功、五分钟后告诉你权重不等于 100%」错在哪？
4. 防重是一层还是几层？每一层防的是哪一种绕过？
5. 插入热点和更新热点是不是同一类问题？计数行被打满时你动哪一侧？
6. 限流只按用户 / 只按接口 / 只按全局，各会怎样？没有压测背书的阈值叫什么？
7. 标出：哪些是设计完成、哪些依赖业务侧同意、哪些必须压完才能写进承诺。

---

## 第三段 · 状态流转 {#q-push}

审批要「下级先提交」。审批人经常看手机。PC 上要已读回执、批量已处理。客户端会断线、会多端、会离线好几天。长连接会把服务端从无状态变回有状态。

1. 短轮询 / 长轮询 / 单向推 / 双向推，各买什么、各付什么。6 万人量级下「纯短轮询」的成本长在哪？（估算，待验证）
2. 只要服务端→客户端这一方向，为什么有人还是不选更省事的单向通道？
3. 实时和可靠打架时，你把哪件事交给推、哪件事交给拉？推送里能不能带待办列表和未读数？
4. 会签 / 或签 / 加签，实例状态要不要单独存一份？不存的话它从哪来？
5. 「业务写库」和「消息发出」不能放进同一个外部事务时，你用什么保证至少发出去？
6. 离线三天的客户端，补过程还是补状态？

---

## 第四段 · 数据呈现 {#q-report}

结算期同一张完成率、分布会被反复打开。计算要沿组织树上卷，明细行量级在十万到百万（设计目标）。封板前数据会变。维度组合如果穷举是指数级，真实访问集中在模板用到的那一小撮。

1. 预计算省的是「计算」还是别的？用频次 × 单次成本写判据。什么时候预计算是净亏？
2. 四档：纯实时 / 实时+缓存 / 定时全量预计算 / 预计算+增量维护。汇总、明细、同比、临时筛选各倾向哪档？为什么增量维护不能当填报期的唯一方案？
3. 结果能不能继续堆在业务库的明细表上跑？分析负载和交易负载抢什么？
4. 维度穷举为什么死？未命中的查询允许报错吗？
5. 预计算路径和实时兜底路径各写一遍指标，会出什么长期事故？你现在有没有解掉？
6. 报表结果要不要带组织树版本？不带的话，「组织改了」和「数据改了」还分得开吗？

---
