# 层账

> **这一页是工作页。** [架构路线总览](/projects/architecture-evolution/)讲判断方法；本页只记账。格子里是**这一层自己的档**，外加一列状态。不要写「我们是 V3」。

状态只准用这四个词：

| 状态 | 意思 |
|---|---|
| **已上线** | 生产在跑，用户能碰到 |
| **已验证** | 本地、压测或演练跑过，**不是**生产规模 |
| **仅方案** | 写过设计，没按该档跑过 |
| **未到** | 这档还没被墙逼到，保持上一档是合理的 |

数值与档位都是**经验包络或设计记录**，不是生产实测。脱敏。没有第三套真实系统时，空表留着，有了再填——**不要为填满而编。**

## 一、怎么改这一页 {#how}

1. 每个系统一张表。层的梯子见总览[现状怎么记账](/projects/architecture-evolution/#matrix)，细则在各层页。
2. **一次只改被墙逼到的那一格**，并改状态。别整表升档。
3. 要动某一格之前，先看该层页的「可跳 / 可不到」。跳过的格子写「未到」或「已跳过」，不要空着让以后的自己猜。
4. 对照用：[个人路径](/projects/architecture-evolution/#my-path)是叙事；**以本页表格为准**。

## 二、系统甲 · 早期单体（已上线） {#sys-a}

约束：一个人能 hold 住的业务系统；文件曾和应用共盘；图片延迟先于库容量到来。

| 层 | 档 | 状态 | 备注 |
|---|---|---|---|
| **架构 L1 共址与拆机** | 库、缓存已迁走；文件仍可在应用机 | 已上线 | 拆的是隔离，不是高可用 |
| **架构 L2 应用** | 单体（按模块分子模块，同一进程） | 已上线 | 聚合 / 垂直拆分未到 |
| **架构 L3 数据** | 独立单机 | 已上线 | 主从未到 |
| **架构 L3 · 分片** | — | 未到 | 单表没撞写墙 |
| **架构 L4 缓存** | 单机 Redis | 已上线 | 哨兵 / Cluster 未到 |
| **架构 L5 文件** | 本机目录 | 已上线 | 独立文件机已跳过 |
| **架构 L5 · CDN** | 图片走 CDN | 已上线 | **提前**：库仍单机 |
| **架构 L6 部署** | 单机 Tomcat + 手工发版 | 已上线 | CI / 云原生未到 |
| **可观测** | 日志文件 | 已上线 | 不在五层梯子上，但要记账 |

**这一列最有用的格子是文件。** 数据和缓存都还在单机，CDN 已经上了——层不同步本身就是账。

## 三、系统乙 · 多租户 SaaS（混杂状态） {#sys-b}

约束：租户规模差一个数量级；账单要强一致；分析查询不能压在线库。同一张表里**三列状态会并存**，这是正常的。

| 层 | 档 | 状态 | 备注 |
|---|---|---|---|
| **架构 L1 共址与拆机** | 已拆完 | 已验证 | 后续档位不再共命运 |
| **架构 L2 应用** | 父子聚合 JAR；往垂直拆分 / 微服务走 | 聚合 **已验证**；拆服务 **仅方案** | 聚合不是微服务 |
| **架构 L3 数据** | 一主二从 + 自动切主（MHA） | 仅方案 | 买的是活下来，不是装得下 |
| **架构 L3 · 分片** | ShardingSphere | 仅方案 | 可不到；没撞墙前不要提前 |
| **架构 L4 缓存** | 主从 + 哨兵 | 仅方案 | Cluster 未到 |
| **架构 L5 文件** | 统一对象存储 | 仅方案 | 独立文件机跳过 |
| **架构 L5 · CDN** | 静态资源可走 CDN | 仅方案 | 可提前，不挡对象存储 |
| **架构 L6 部署** | 容器化；往 K8s | 容器 **已验证**；编排 **仅方案** | 与应用是否微服务解绑 |
| **可观测** | 指标 + 日志 + 链路 | 仅方案 | 三支柱要能对上 `traceId` |

> 聚合与容器化有本地验证；MHA、分片、K8s 编排写出来是判断依据，**不是声称已具备生产规模**。见[项目题的三条红线](/projects/#interview)。
