# 架构 L2 应用

> **口径说明**：这一页是[架构路线](/projects/architecture-evolution/)的架构 L2 **应用线**。页内 V1～V4 **只在本页内可比**，不是系统总版本号，也不要求和库、缓存、文件对齐。前置是 [架构 L1 共址与拆机](/projects/architecture-evolution/colocation/)。

应用线不是「单体 → 微服务」一步。中间两档解决的是**工程边界**和**部署边界**，不要跳。

```text
V1 单体（一个模块，一个进程）
  └─▶ V2 父子聚合 / 模块化单体（多模块，仍一个部署单元）
        └─▶ V3 垂直拆分（几个独立部署的「小单体」，库往往还共享）
              └─▶ V4 微服务（独立进程 + 独立数据 + 治理）
```

可以停在聚合。跳过 V2/V3 直接上 V4，是把一个难改的系统变成一群难改的系统。

## 一、V1 单体 {#monolith}

<span id="app"></span>

| 项 | 内容 |
|---|---|
| **解决了上一档什么** | 起步最快，事务是本地的。上一档是「还没系统」 |
| **触发信号（经验值）** | 项目起步，边界还不稳 |
| **怎么拆** | 按包分层即可，不要先拆仓库 |
| **升完能撑什么** | 一个进程能吃下的 QPS 与发布节奏；调试和事务最便宜 |
| **新上限** | 一处改动全量发布；一处 bug 拖垮全部；无法按模块单独升配 |

和数据有没有主从无关。库可以已经迁走，应用仍是这一档。

## 二、V2 父子聚合 {#modular}

| 项 | 内容 |
|---|---|
| **解决了上一档什么** | 依赖漂移、横切能力每处抄一遍 |
| **触发信号（经验值）** | 模块变多，Spring Cloud / 日志 / 鉴权 / 幂等开始各写各的；新人不知道该引哪几个包 |
| **怎么拆** | parent POM 统一版本；横切收成**一个框架 JAR**。依赖单向：biz → framework → 三方，biz 之间禁止互引 |
| **升完能撑什么** | **运行时体量不变**（仍一个进程）。换来的是：新模块只引一个坐标就拿到约定，升级可以灰度 |
| **新上限** | **发布和扩容仍绑在一起**。这不是微服务——进程没拆，库也没拆 |

**不算微服务。** 产出是工程约定，不是拓扑。落地样本：[框架聚合 JAR](/projects/property-saas/microservice-to-k8s/#framework-aggregation)。

## 三、V3 垂直拆分 {#vertical}

| 项 | 内容 |
|---|---|
| **解决了上一档什么** | 一个进程里两块业务已经互相拖累 |
| **触发信号（经验值）** | 有清晰业务边界，且一边需要独立发布或独立升配；共享库还暂时能接受 |
| **怎么拆** | 按业务拆成几个部署单元，每个仍是「小单体」。先拆**无状态应用**，数据归属先划清再迁库 |
| **升完能撑什么** | 可以按系统加机器，故障半径缩到这一个单元 |
| **新上限** | 若库仍共享，数据仍是单点；跨系统调用开始出现，但还没有完整治理 |

**这一档才第一次出现「两个部署单元」。** 多实例会逼[文件离开本机盘](/projects/architecture-evolution/file/)；那是文件线被应用线逼动，不是应用已经到了微服务。边界怎么划见[拆分粒度](/methodology/service-granularity)；跨服务归属必须上会，见[方案评审](/projects/toolkit/review/)。

## 四、V4 微服务 {#microservice}

| 项 | 内容 |
|---|---|
| **解决了上一档什么** | 垂直拆分之后，共享库 / 共享发布仍卡住独立演进 |
| **触发信号（经验值）** | 边界稳定，独立数据的收益已经能说清；组织上也是不同节奏的团队 |
| **怎么拆** | 独立库、独立发布、注册发现、超时与重试、链路、配置。跨系统一致走本地事务 + 消息 + [对账](/methodology/reconciliation)，不要默认上分布式事务 |
| **升完能撑什么** | 按**服务**扩容和发布；故障隔离到服务级 |
| **新上限** | 运维、调试、一致性、发布协调全部上升。拆错就变成[分布式单体](/methodology/service-granularity) |

**验收看数据是否真的独立。** 还在共享库上画服务边界，档位只买了一半。部署线与这一档解绑：可以微服务仍手工发版，见 [架构 L6 部署](/projects/architecture-evolution/deploy/)。
