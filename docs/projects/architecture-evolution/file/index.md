# 架构 L5 文件

> **口径说明**：这一页是[架构路线](/projects/architecture-evolution/)的架构 L5 **文件线**。文件**没有主从这一档**：副本是全量拷贝，不增加可装容量。主轴是离开本机盘、换介质。独立文件机**可跳过**；CDN **可提前**。触发常常不是「文件先涨到 TB」，而是[应用变成多实例](/projects/architecture-evolution/app/#vertical)或图片已经慢了。

## 一、主路与两条岔路 {#map}

不为凑四档把 NFS 写成必经。真实顺序更像：

```text
本机磁盘
  ├─▶ 对象存储 ─────────────────────────▶ 对象存储 + CDN
  └─▶ 独立文件机（可跳过）──▶ 对象存储 ──▶ CDN

CDN 可提前：单体 + 本机上传 + 图片走 CDN
           （库还可以是独立单机）
```

| 档 | 必经？ | 在买什么 |
|---|---|---|
| **本机磁盘** | 起步几乎都在这 | 实现最简单；第二台应用一上就到期 |
| **独立文件机** | **可跳过** | 多实例读到同一份；仍是一台盘、一个单点 |
| **对象存储** | 离开本机之后的主路 | 不再自己运盘；容器化之后本地盘默认不可信 |
| **CDN** | **可提前**，也可叠在对象存储上 | 卸源站读带宽和远距离延迟 |

早期已上线系统常见的形态就是「本机目录 + 图片 CDN」，中间没有文件服务器。多租户方案则往往直接统一对象存储。两边都可以没有 NFS。

## 二、本机磁盘 {#local}

<span id="file"></span>

| 项 | 内容 |
|---|---|
| **解决了上一档什么** | （共址或应用本机）实现最简单 |
| **触发信号（经验值）** | 单实例、文件量小 |
| **怎么拆** | 先把路径做成配置，不要写死 `./uploads` |
| **升完能撑什么** | 单盘容量；进程在就找得到文件 |
| **新上限** | **第二台应用实例**一上，文件就开始对不上；磁盘满则写失败 |

共址期文件可以继续留在应用机上，不必和 MySQL 一起迁。见 [架构 L1 共址与拆机](/projects/architecture-evolution/colocation/#split)。

## 三、独立文件机（可跳过） {#fileserver}

NFS / SMB 这一档解决的是「多实例后本地盘不一致」，**不增加容量**，自己还是单点。2018 年以后很多系统从未经过这一档：本机直接上对象存储。

| 项 | 内容 |
|---|---|
| **解决了上一档什么** | 多实例后本地盘不一致 |
| **触发信号（经验值）** | 应用从 1 变成 N，用户上传在 A 机器、请求打到 B；**且**还不能 / 还不想接对象存储 |
| **怎么拆** | NFS / SMB 等独立存储，应用只认 URL 或挂载点 |
| **升完能撑什么** | 多实例读到同一份文件。容量 = **那一台文件机**的盘 |
| **新上限** | 文件服务自己是单点；性能和备份仍绑在这台机上 |
| **为何可跳** | 对象存储同时解决「多实例一致」和「不再运盘」。没有必要为了「看起来像演进了一步」先上 NFS |

## 四、对象存储 {#object}

| 项 | 内容 |
|---|---|
| **解决了上一档什么** | 本机盘或多实例不一致，或文件机的容量、跨机房和磁盘运维 |
| **触发信号（经验值）** | 应用要多实例；容量要弹性；不能接受文件机单点；**容器化之后本地盘默认不可信** |
| **怎么拆** | 上传改远端 API；补失败重试、权限、签名。路径带租户段（SaaS） |
| **升完能撑什么** | 容量按对象存储的包络（近似只受账单约束，不受单盘约束） |
| **新上限** | 尾延迟高于本地盘；失败模型从「磁盘满」变成「网络超时」 |

容器一删本地文件在哪，见 [Docker](/cloud-native/docker/)。冷数据进湖表见 [Lakehouse](/bigdata/lakehouse/#three-tiers)，不在本页展开对象存储内部。

## 五、CDN（可提前） {#cdn}

CDN 不是对象存储的「下一档必修」。静态资源延迟先到时，**库还是单机、文件还在本机**，也可以先上 CDN。

| 项 | 内容 |
|---|---|
| **解决了上一档什么** | 源站读带宽和远距离延迟 |
| **触发信号（经验值）** | 静态资源（图、包、下载）的延迟或回源带宽成为体验瓶颈 |
| **怎么拆** | CDN 回源到本机（过渡）或对象存储；发布流程加上刷新 / 预热 |
| **升完能撑什么** | **读**从源站卸掉，命中后的延迟按边缘节点包络 |
| **新上限** | 刷新与回源策略成为新问题；动态文件不要走 CDN 当数据库用 |
| **为何可提前** | 瓶颈是用户侧延迟，不是存储容量。图片 CDN 和 MySQL 分片不是同一件事 |
