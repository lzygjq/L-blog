# 架构 L6 部署

> **口径说明**：这一页是[架构路线](/projects/architecture-evolution/)的架构 L6 **部署线**。它和 [架构 L2 应用](/projects/architecture-evolution/app/)的单体 / 微服务**不是同一条梯子**：可以微服务仍手工发版，也可以单体已经在 K8s 上。脚本多实例可跳；不必为了凑档先养一轮雪花机器。

```text
手工发版
  ├─▶ 脚本 + 多实例（可跳）──▶ CI 流水线 ──▶ 云原生
  └─▶ CI 流水线 ────────────────────────▶ 云原生
```

多实例一旦出现，[文件必须离开本机盘](/projects/architecture-evolution/file/)——那是文件线被部署形态逼动。

## 一、手工发版 {#manual}

<span id="deploy"></span>

| 项 | 内容 |
|---|---|
| **解决了上一档什么** | 起步 |
| **触发信号（经验值）** | 一台机器、一个人发 |
| **怎么拆** | `scp` / 上传 / 重启 |
| **升完能撑什么** | 一台、一次、一个人能看住的变更 |
| **新上限** | 不知道线上跑的是哪一包；回滚靠记忆；第二台机器开始漂移 |

## 二、脚本 + 多实例（可跳） {#scripts}

| 项 | 内容 |
|---|---|
| **解决了上一档什么** | 一台手工搞不定 |
| **触发信号（经验值）** | 要起第二台，或要在深夜重复一套步骤；**且**还没有 CI |
| **怎么拆** | 启动脚本、反向代理、健康检查靠自己写。多实例前文件必须离开本机盘 |
| **升完能撑什么** | 能水平加应用机器；步骤可重复，但机器仍是「雪花」 |
| **新上限** | 环境之间靠改配置文件；出事对不上版本；扩容仍靠人盯脚本 |
| **为何可跳** | 现在很多系统从手工直接进 CI：制品可追溯，机器也不用先养成雪花。跳过这一档的前提是文件已经不在本机 |

## 三、CI 流水线 {#ci}

| 项 | 内容 |
|---|---|
| **解决了上一档什么** | 产物不可追溯、反馈太慢 |
| **触发信号（经验值）** | 已经出现「线上那包是谁打的」；合并后要等很久才知道能不能上 |
| **怎么拆** | 构建 → 测试 → **不可变制品**（禁止 `latest` 当生产标签）→ 可重复部署。门禁失败即停 |
| **升完能撑什么** | 每次发布对应一个制品 ID；回滚是发上一个制品，不是在服务器上改文件 |
| **新上限** | 数据变更仍可能不可逆——应用能退、库不能退，必须走[扩展-收缩](/cloud-native/cicd/rollback-and-migration#expand-contract) |

自动化是「能重复」到「能追溯、能回滚制品」。云原生是下一档，不必一次跳到 GitOps。

## 四、云原生 {#cloud}

| 项 | 内容 |
|---|---|
| **解决了上一档什么** | 扩容和自愈靠人 |
| **触发信号（经验值）** | 副本数、挂了拉起、多环境一致，已经不是脚本能稳定完成的 |
| **怎么拆** | 镜像 + 编排（探针、资源、滚动）；再往上才是 GitOps / 渐进式放量。先无状态应用，有状态组件不要一起搬 |
| **升完能撑什么** | 以副本和声明为包络：挂了由控制器拉起；扩容改期望副本而不是再写一台脚本 |
| **新上限** | 有状态、本地盘、定时任务、会话粘滞会把「声明式」打回脚本时代。编排不是把数据库也塞进 Pod 这么简单 |

容器化之后本地盘默认不可信，会回头逼[文件走对象存储](/projects/architecture-evolution/file/#object)。
