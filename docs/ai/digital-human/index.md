# 数字人 · 导览

数字人（Digital Human / Avatar）是「AI 能力集成」中最典型的**多模态应用形态**：它把 ASR、LLM、TTS、图像/3D 渲染、实时音视频传输串成一条完整链路，最终以"会说话的形象"交付给用户。

与板块内 Spring AI 那一线（把大模型能力接入 Java 服务）相比，数字人的特殊之处在于**它有一半是终端与实时性工程**——AI 效果好不好只决定一半体验，另一半取决于渲染模式选型、网络链路和终端稳定性。

## 一、先分清三个维度

数字人不是一个大类，而是三个正交维度的组合。选型混乱的根源，通常是这三个维度没拆开。

### 维度一：形象类型

| 类型 | 生成方式 | 成本 | 拟真度 | 典型场景 |
|---|---|---|---|---|
| **照片数字人** | 单张照片驱动 | 最低 | 低（口型为主，头部动作有限） | 名片、邀请函、轻量视频 |
| **2D 真人** | 真人视频克隆（小样本 / 精品） | 中 | 高（接近实拍） | 口播视频、客服、直播 |
| **3D 卡通** | 模板 + 捏脸 | 中 | 风格化 | 品牌 IP、儿童内容 |
| **3D 超写实** | 建模 / 扫描 + 绑定 | 最高 | 最高（可全角度） | 展厅、高价值品牌形象 |

**关键判据**：需要"自由视角 + 全身动作"才上 3D；只在固定机位做口播，2D 真人的性价比碾压 3D。

### 维度二：渲染模式（本文最核心的选型项）

| 维度 | **云渲染** | **端渲染** |
|---|---|---|
| 算力位置 | 云端 GPU | 终端本地 |
| 终端硬件要求 | 低（能解码视频即可） | 高（需支撑实时渲染） |
| 网络依赖 | **强**（实时音视频流，断网即中断） | 弱（弱网/离线可用） |
| 服务端成本 | 高（每路会话独占云端 GPU 资源） | 低（仅信令与 AI 推理） |
| 并发能力 | 受云端 GPU 池规模限制 | 高并发友好 |
| 形象质量上限 | 高（不受终端性能约束） | 受终端算力约束 |
| 形象更新 | 云端统一更新，终端无感 | 需下发资源包 / 升级终端 |
| 协议 | WebRTC（低延迟）/ RTMP（高兼容） | 私有引擎 + 资源包 |

一句话判据：**终端多、要并发、网络不稳 → 端渲染；终端少、要画质、网络可靠 → 云渲染。**

### 维度三：交互形态

| 形态 | 说明 | 实时性要求 |
|---|---|---|
| **视频生成** | 输入文案，离线合成视频文件 | 无（分钟级产出可接受） |
| **实时互动** | 双向对话，边听边说，可打断 | **高**（端到端延迟敏感） |
| **直播** | 单向播报为主 + 弹幕/评论互动 | 中（延迟可放宽到秒级） |

## 二、一条完整的实时互动链路

理解链路是排查问题的前提。云渲染互动数字人的一次问答，实际经过这些环节：

```
访客说话
  └─▶ 终端麦克风采集
        └─▶ 上行网络传输 ──┐
                            │  （云渲染时，音视频与渲染都在云端）
        ┌───────────────────┘
        ▼
   云端 ASR 语音识别
        ▼
   LLM 语义理解与回复生成（可接知识库 / RAG）
        ▼
   TTS 语音合成（音色决定"是谁在说"）
        ▼
   云端渲染引擎：语音 → 唇形 + 表情 + 动作驱动
        ▼
   视频编码 ──▶ 下行推流 ──▶ 终端解码播放
```

**排查问题的定位方法**：把链路按段切开，先确认断在哪一段。

| 现象 | 最可能的环节 |
|---|---|
| 有画面但不出声 | 终端音频输出 / 音量 / 通道配置 |
| 有声但口型不动 | 云端渲染驱动环节，或音画不同步 |
| 完全黑屏 | 进房失败（鉴权/额度）、网络不可达 |
| 能对话但延迟极高 | 网络往返质量，或 LLM 推理排队 |
| 反复断连 | 网络抖动、token 过期未刷新 |

## 三、选型四问

拿到一个数字人需求，按顺序回答这四个问题，方案基本就定了：

1. **形象要多真？** 决定 2D / 3D、公共形象库还是定制克隆。
2. **终端是什么？** 无人值守设备、网页、大屏还是手机——这一问直接决定 SDK 形态与渲染模式。
3. **网络可不可控？** 有线专线能拉 → 云渲染可行；依赖 4G/WiFi 且位置不固定 → 优先端渲染。
4. **谁来做"最后一公里"？** 供应商给的是 SDK 和 Demo，**终端工程（自启、全屏、常驻、断线重连）始终是自己的开发量**，这部分常被低估。

> 第 4 问是新手最容易踩的坑：以为"拿到 SDK 就等于拿到数字人产品"。实际上 SDK 解决的是"画面与对话"，产品化还差一整层终端工程。

## 五、常见落地形态速览

| 形态 | 渲染 | 交互 | 关键约束 |
|---|---|---|---|
| 展厅 / 导览终端 | 云渲染为主 | 实时问答 | 无人值守，需自启 + 常驻 + 防息屏 |
| 智能客服 | 端渲染为主 | 实时问答 | 高并发，需控制单会话成本 |
| 直播带货 | 云渲染 | 单向 + 弹幕 | 长时间稳定，需断流自动恢复 |
| 口播视频生产 | 云端离线合成 | 无 | 批量吞吐与排队调度 |
| 交互大屏 / 数字员工 | 云渲染 | 实时问答 + 业务系统对接 | 需与既有业务数据打通 |
