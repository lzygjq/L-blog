# 发布与多端打包

## 一、小程序版本体系：四层语义

| 版本 | 谁可见 | 怎么来 |
|---|---|---|
| 开发版本 | 开发者 | 开发者工具实时预览 |
| 体验版本 | 项目成员 + 体验成员 | 工具「上传」后设为体验版，二维码分发 |
| 审核版本 | 微信审核团队 | 后台提交审核（1 小时~数天不等） |
| 线上版本 | 全量用户 | 审核通过后手动发布（可定时发布） |

流程：**上传 → 设体验版（测试）→ 提交审核 → 发布**。每次上传要填版本号 + 项目备注，备注写清本次变更——后台版本管理面板就靠它回溯。

三个容易忽视的点：

1. **审核是异步且有拒绝率的**：类目不符、诱导分享、功能不完整都会拒——首次提审预留 2~3 天缓冲，赶运营节点要倒排；
2. **「重新审核」与撤回**：审核中不能再次提交，发现 bug 只能撤回重传，所以提审前的体验版回归测试不能省；
3. **回退**：线上版本支持回退到上一版（2 小时内生效），但不是万能——数据结构类变更要先想兼容再发版。

## 二、多环境管理：双 AppID 切换

开发/生产通常各有一个 AppID（不同主体或不同小程序），manifest（uni-app）里同时配置，构建时按环境取用：

```js
// 各环境常量：接口域名 + AppID 成对管理
const env = {
  dev:  { baseUrl: 'https://test-api.example.com', appid: 'wx1111...' },
  prod: { baseUrl: 'https://api.example.com',      appid: 'wx2222...' }
}
```

**纪律比技术重要**（这是多环境最常见的翻车点）：

1. **成对管理**：切环境必须「域名 + AppID」一起切——只切域名不切 AppID，会出现「测试小程序连生产库」的事故；
2. 正式配置注释保留并标注，便于回切；
3. CI 化的团队用构建时注入环境变量（HBuilderX 自定义发行 / CLI 模式 `--env`），消灭手工切换。

## 三、H5 端打包：不要低估的差异

uni-app 发行到 H5 看似一条命令，实际差异清单：

| 差异点 | 处理 |
|---|---|
| 路由 | H5 是真实 URL，`pages.json` 里可配路由模式（hash/history）与 base |
| 跨域 | 小程序无跨域概念，**H5 有**——开发期 manifest 配代理，生产靠 Nginx 反代或后端 CORS |
| 登录 | `wx.login` 不存在，H5 走公众号网页授权（OAuth2）或账号密码——条件编译收敛到适配层 |
| 资源 | 相对路径 + CDN 前缀（`base` 配置），注意 publicPath 与部署目录一致 |
| 分享 | 小程序转发卡片 vs H5 蜘蛛/微信 JS-SDK，两套逻辑 |

**部署**：H5 产物是纯静态目录，Nginx 托管即可（history 模式要配 try_files 回退），正好复用[云原生板块](/cloud-native/)的静态站发布链路。

## 四、App 端打包（简述）

uni-app 出 App 两条路线：

- **webview 渲染**（默认）：页面即 Vue 编译产物在 webview 里跑，开发成本低，性能中等；
- **nvue / uni-app x**：原生渲染组件，长列表/动画性能高，但样式与组件子集受限。

发布需要证书（Android 自签名 keystore / iOS 证书 + 描述文件）、云打包（DCloud 云端，免本机环境）或离线打包（集成进原生工程）。App 端还有热更新（wgt 资源包）能力，规避应用商店审核周期——但注意商店对热更新内容边界的合规要求。

## 五、上线前检查清单

发版前过一遍（按翻车频率排序）：

1. **环境核对**：接口域名、AppID、地图/支付等三方 key 指向生产——「测试配置带上线」是最高频事故；
2. **合法域名**：生产域名已在小程序后台登记（request/uploadFile/downloadFile 三类）；
3. **包体积**：主包 < 2MB，超了先查 static 大图（应上 CDN）再查分包拆分；
4. **降级与兜底**：弱网 loading、接口失败重试、空状态展示；
5. **版本兼容**：用到的 API 检查基础库最低版本，低版本用户是否给出升级引导；
6. **隐私合规**：`getUserProfile` 等敏感 API 的用途声明（后台隐私协议必填项），缺了直接拒审；
7. **体验版全流程回归**：登录 → 核心链路 → 支付（沙箱/小额真实支付）→ 分享回流。

## 六、面试问答

**Q: 小程序发版后发现严重 bug，怎么办？**
先止血再修复：能靠配置/开关回退的立即回退线上版本（2 小时生效），不能回退的走「加急审核」通道（有次数额度）；同时后端侧用开关降级关联功能兜底。根因复盘后重走提审流程。

**Q: 多环境配置怎么做才能不翻车？**
域名、AppID、三方 key 全部环境化集中管理，构建时注入，禁止运行时手工切换；发布流水线里加「环境指纹」自检（启动时上报当前环境标识，运维可监控误连）。

**Q: 小程序和 H5 同时发布，怎么管理版本节奏？**
共享代码库 + 条件编译隔离端差异，版本节奏解耦：小程序受审核周期约束（提前预留），H5 随时可发。公共变更先合主干，再分别走各端发布流水线。
